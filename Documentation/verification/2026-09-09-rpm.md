# RPM reader 検証記録(2026-09-09)

対象コミット: (未確定)
実装: `Sources/KaitoKit/Formats/Rpm/`(RpmHeader / RpmReader)

## 1. 方法と、この形式で digest を直接比較できない理由

XADMaster はブラックボックスの展開オラクルとしてのみ使う(design.md §10)。

ただし **RPM では総合 digest の直接比較ができない**。XADMaster は `.rpm` に対して
payload の圧縮済みブロブを 1 entry 返すだけで、中の cpio へ降りないからである。
KaitoKit は `.tar.gz` で既に中へ降りる設計(XADMaster は `tar.tar` を 1 個返す)なので、
RPM でも payload の cpio entry を直接公開する方針を採った。

そこで検証は 2 系統に分けた。

1. **降りる経路**: payload を自前で取り出して XADMaster に渡した結果と、
   KaitoKit が `.rpm` を直読みした結果を突き合わせる。
2. **blob fallback の経路**: XADMaster が返す 1 entry と byte 単位で一致することを見る。

さらに RPM ヘッダ自身が持つ `RPMTAG_FILEDIGESTS`(tag 1035、sha256)を第 3 の
独立した参照値として使える。

## 2. 形式の実測

fixture は macOS 上の `rpmbuild` 6.1.0 で生成した(black-box writer としてのみ使用)。

| 領域 | 実測 |
|---|---|
| lead | 96 byte。magic `ED AB EE DB`、major=4、type 0=binary / 1=source |
| signature header | offset 96。magic `8E AD E8 01`、nindex / hsize |
| padding | **signature header の後だけ** 8 byte 境界へ。実測 sigEnd=4450、pad=6 |
| main header | 上記の直後。後ろに padding は無い |
| payload | main header の直後から EOF まで |

```
sigEnd    = 96 + 16 + sigNindex*16 + sigHsize
mainStart = sigEnd + ((8 - sigEnd % 8) % 8)
payload   = mainStart + 16 + mainNindex*16 + mainHsize
```

全 fixture で `payload 開始 + payload 長 == ファイル長`。

### index entry の落とし穴

index entry は **tag 番号順**に並んでおり、data store 内の offset 順ではない。
最小 tag である region entry(62 / 63)の data は store の末尾近くを指す。
「次の entry の data は今の entry の直後から始まる」と仮定する reader は即座に壊れる。
KaitoKit は tag を引いて offset / count から読むので影響しない。

region trailer は BIN・count=16 で、負の offset を持つ入れ子 index entry の形をしている
(実測 `0000003f 00000007 fffffc70 00000010` = tag 63 / type 7 / offset −912 / count 16)。
不透明な BIN として無視するのが正しい。

### payload の cpio 変種

| package format | payload magic | 対応 |
|---|---|---|
| 古典(`_rpmformat 4`、実世界の配布 package)| `070701`(newc)| **中へ降りる** |
| rpm 6 の新形式 | `07070X`(簡略 cpio)| blob fallback |

`07070X` は 8 桁 hex の index だけを持ち、名前・サイズ・mode は header 側の
BASENAMES(1117)/ DIRNAMES(1118)/ DIRINDEXES(1116)/ FILEMODES(1030)/
FILELINKTOS(1036) にある。rpm.org は 4 GiB 以上のファイル用として rpm 4.12 で
導入されたと説明するが、実測では rpm 6.1.0 の既定 package format が
小さいファイルだけの package でもこれを書いた。復元は別 issue(`cooViewer-c1vj.4`)。


通常ファイル 3 件の digest は、RPM ヘッダ自身の `RPMTAG_FILEDIGESTS`(tag 1035)が

XADMaster に渡した結果、(3) package の作者が書いた digest、の三つが揃っている。

## 5. 圧縮方式は宣言ではなく実体で決める

当初の実装は `RPMTAG_PAYLOADCOMPRESSOR`(tag 1125)だけを見ていた。
実測した rpm 6.1.0 では tag 不在 = 無圧縮だったのでそれで通ったが、
公開資料によれば **tag が導入される前の古い package では tag が無く、その場合の
既定は gzip** である(当時の LSB は PAYLOADCOMPRESSOR='gzip' を要求していた)。
「tag 不在 = 無圧縮」と書いた仕様は、測った 1 実装の挙動を一般化した誤りだった。

再現して確かめた:

| 入力 | 訂正前 | 訂正後 |
|---|---|---|
| tag 不在 + gzip payload(古い package の再現)| blob 1 entry | **6 entry / `058d0a9d…`** |
| tag が `none` と嘘をつく + gzip payload | blob 1 entry | **6 entry / `058d0a9d…`** |

現在は payload 先頭の magic で codec を決め、tag は magic が判別できないときの
hint としてのみ使う。`0707` は無圧縮 cpio、`1F 8B` gzip、`42 5A 68` bzip2、
`FD 37 7A 58 5A 00` xz、`28 B5 2F FD` zstd。
宣言値は `rpmPayloadCompressor` にそのまま残し、実体と食い違うときだけ
`rpmPayloadCompressorDetected` を併記する。

payload の復号に失敗した場合は blob へ fallback せず、開封時に失敗させる。
壊れたデータを黙って別の形で見せない方針。

訂正で足した regression test は、既存 fixture の bytes をテスト中だけ組み替える
(fixture 自体や header の長さは変えない)。

| 組み立て方 | 確認内容 |
|---|---|
| rpm-none の header + rpm-gzip の payload | 元 header に tag 1125 が無いこと、6 entry、宣言 key 無し、検出値 gzip |
| rpm-gzip の tag 値 `gzip` を同じ長さの `none` に置換 | 6 entry、宣言値 `none` を保存、検出値 gzip |

どちらも保存順の全 golden row と総合 digest
`058d0a9d9c28c2133c547d0a13fed38414a921b21f2b4109fef179c979d9150c` を検証する。

## 6. XADMaster との差

| 項目 | XADMaster | KaitoKit |
|---|---|---|
| payload | 圧縮済みブロブ 1 entry | 中の cpio entry を直接公開 |
| 無圧縮 payload の名前 | `kaitotest.cpio.gz`(**誤り**)| — (中へ降りる) |
| zstd payload の名前 | `kaitotest.cpio`(拡張子なし)| `kaitotest.cpio.zst` |
| zstd の展開 | 不可 | 不可(`cooViewer-c1vj.3`) |
