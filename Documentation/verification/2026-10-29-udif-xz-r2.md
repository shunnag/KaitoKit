## Scope and implementation

- **9 — byte-sized UDIF cache.** Retain at least a 64 MiB working set, or the
  existing four reservations for larger chunks, capped by
  `resolvedParallelDecodeMemory()`. Cache and pending work share the existing
  reservation budget. LZFSE reservations still include packed input bytes.
- **11 — retain useful speculation.** On seeks and window changes, discard only
  unclaimed pool tickets. Running work retains its reservation; completed work,
  including deferred errors, enters the same bounded LRU at the next consumer
  operation. Pending work from previous windows limits further speculative
  fills. Demanded reads never wait on unrelated speculation; they use the
  existing Budget reservation / uncached serial fallback and may assist their
  own queued ticket inline. A leaf's CancellationError retires that Work;
  uncancelled consumers retry it, and it never reaches the LRU. Reader-level
  cancellation and destruction still abandon all work as before.
- **12 — adaptive XZ grouping.** Default target is the larger of the largest
  block and 1 MiB, with the remaining size target capped at 16 MiB and based on
  `decodedSize / (2 * requestedWorkers)`. The request is bounded by the shared
  pool and block count. The existing held-byte calculation and two spare-job
  reservations still cap actual workers. Explicit test targets are unchanged.
- **13 — native ULMO decoding.** Use a bounded chunk source and
  `ParallelXZDecompressor(workers: 1, expectedSize: chunk.byteCount)`. This reuses
  native eligibility checks and Compression replay on native failure. The UDIF
  drain still verifies exact size, extra output, completion, and checksums.

No new unsafe memory operations were introduced. ReaderOptions continues to
resolve DecodePowerPolicy and explicit decodeThreads before these paths run.
There is no nested parallelism in ULMO leaves.

## Concurrency-review follow-up

The independent review confirmed two cache defects. No equivalence defect was
reported. The production change in this follow-up is confined to
`UDIFChunkCache.swift`; `UDIFImage.swift`, `ParallelXZDecompressor.swift`, and
`LeafDecodePool.swift` are unchanged from the reviewed implementation.

1. `Work.perform` no longer publishes CancellationError as a shared decode
   result. It marks only that Work abandoned and wakes its waiters. The inline
   owner observes its own Task cancellation in `value`; uncancelled readers
   retire the matching pending Work and retry. Recollection also removes
   abandoned pending work, and LRU insertion rejects abandoned work. Genuine
   decode errors continue to be shared/cached as before.
2. The arbitrary `pending.first` wait loop is removed. Every read recollects
   completed/abandoned pending work under the cache lock and proceeds to its
   own demanded leaf. It cannot execute or wait on an unrelated speculative
   leaf. Speculative fills retain their resolved-thread bound, and retained
   work still uses the same Budget. The existing unreserved, uncached serial
   fallback for insufficient parallel memory is unchanged.

`UDIFChunkCacheConcurrencyTests` provides three deterministic regressions:

- Cancel a gated leaf in its executing Task (both serial and forced-inline
  paths), then read it from an uncancelled consumer twice and check reuse of an
  unrelated LRU entry. The forced-inline pool uses `executor: { _ in }`, so no
  Dispatch worker can claim the ticket first.
- Keep both speculative leaves unstarted with that executor and gate either
  one if the old loop chooses it. A demand for a third chunk must finish before
  either gate opens and must not decode either speculative chunk inline.
- Repeat with a real capacity-one pool and one already-running gated leaf.
  Both progress tests release their gates even on assertion failure and check
  the reservation peak against their explicit four-chunk Budget. They do not
  depend on Dictionary iteration order.

Before the fix, all three tests fail: the uncancelled reader receives
CancellationError and both progress tests time out at two seconds. XCTest
reports **3 tests, 5 failures (2 unexpected), 4.422 s**. With the fix the same
three pass in **0.283 s**. The wider targeted run passes **96 tests, 1 skipped,
0 failures, 51.637 s**; the ASan release subset passes **69 tests, 0 skipped,
0 failures, 18.566 s**, with no sanitizer findings.

The regenerated before/after corpus comparison again matches in all **264
observations**, including **164 error outcomes**. Both complete outcome JSONs
have SHA-256 `6319271d90225ba32c6ae9c8ee3963a6c367087d908f6595cdb946511ded0650`.
Tar input timestamps differ from the first verification's regenerated corpus;
