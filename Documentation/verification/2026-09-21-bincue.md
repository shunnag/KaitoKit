# BIN/CUE 生 sector CD image（2026-09-21）

環境: macOS 27.2 / Apple Silicon。独立した生 sector reader は導入されていない（7-Zip 26.03、bsdtar、hdiutil は
2352 byte image を開けないことを 2026-09-20 の候補調査で確認済み）。

## 実装と範囲

- `RawSectorByteSource`（`Sources/KaitoKit/Formats/ISO/RawSectorImage.swift`）: 生 sector image を 2048 byte の
  論理 block だけの `ByteSource` に写す。`ISOReader` / `UDFReader` の入口（`wrapUnlessPlainImage`）と
  `FormatDetector`（CD001 / UDF の固定 offset probe の後）で使う。新しい `ArchiveFormat` case は無く、
  `.iso` / `.udf` として開く（候補調査の「MDF / BIN → iso の alias」の方針）。
- 並びの判定（`detect`）: 先頭と 2352 / 2448 byte 目に ECMA-130 §14.1 の sync（`00 FF×10 00`）があれば 2352 / 2448
  byte sector。logical sector 16 の header byte 15（Sector Mode）が 1 なら user data は 16 から、2 なら 24（8 byte
  sub-header）と 16 を候補にし、logical sector 16 の先頭 8 byte に ISO 9660 の volume descriptor（`CD001`）か ECMA-167 の認識列
  （`BEA01`）が見える位置を採る。Mode 0 やどちらにも見えない image は生 sector image と見なさない。sync が無ければ
  2336 byte sector（sub-header 8 + user data 2048 + trailer 280）として同じ probe を 1 回だけ行う。
- 読み取り: 32 sector ずつまとめて読み、user data を写す。末尾の sector は trailer が欠けていても user data まで
  揃っていれば数える（`RawSectorLayout.count`）。user data の途中で切れていれば `truncated`。EDC / ECC /
  sub-header / sub-channel は読まない。
- `CueSheet`（`CueSheet.swift`）: `.cue` を URL で開いたとき、本文（≤ 1 MiB、tab / CR / LF 以外の制御文字を
  含まない）から `FILE` 行と `TRACK` 行だけを読み、最初の `MODE*` track が属する `FILE`（無ければ最初の `FILE`）
  を同じ directory から `openRegularFile` で開く。引用符あり / なし、`C:\...\` の Windows path（最後の要素だけ
  使う）、UTF-8 / Shift_JIS / CP1252 の名前に対応。参照先が無ければ `notFound`、`.cue` を Data で開くと従来どおり
  `unsupportedFormat`。`ArchiveReader.open(url:)` と `FormatDetector.detect(url:)` の両方で、分割 volume の判定の
  後に試す。`reopen()` は image の source を再検出するのでそのまま動く。

## 出自

ECMA-130 2nd edition §14（`inbox/bincue/ecma-130.pdf`、SHA-256
`576fb91e38e850b7597767ea48402a33e79a89ae4f7d41290e884142ad47f7b8`）の sector 配置だけを仕様入力にした。
CD-ROM XA の sub-header（Philips / Sony の System Description、非公開）と CUE sheet（正式な公開仕様無し）は読まず、
次のとおり黒箱と一般に知られた綴りで補った。

| 点 | 扱い |
| --- | --- |
| Mode 2 の user data 位置 | 24 と 16 を候補にして `CD001` / `BEA01` の位置で決める。sub-header の中身（file / channel / submode / coding）は解釈しない。Form 2（2324 byte）の sector は先頭 2048 byte だけが見える |
| 2448 byte sector | sync が 2448 byte 周期で並ぶことで判定。後ろ 96 byte は読まない |
| 2336 byte sector | sync 無し。`CD001` が 16 × 2336 + 8 の位置にあることだけで判定 |
| header の MSF | 検証しない（multi-file cue の後続 file は絶対時刻が 0 から始まらない）。image の先頭が ISO の LBA 0 である前提で、track の pregap（cue の `INDEX 00`）を含む image は logical sector 16 がずれるため検出されない |
| EDC / ECC | 検証しない。独立 oracle が無く、誤った実装で正しい image を拒む危険の方が大きい |
| CUE | `FILE "<name>" <type>` と `TRACK <nn> <type>` の綴り。`REM` / `INDEX` / `PREGAP` などは読み飛ばす |

T10 の MMC 草案（READ CD の sector 形式に XA の記述がある）は guest 登録が要るため取得しなかった。libcdio /
cdrdao / bchunk / XADMaster などの実装 source は開いていない。

## 独立した検証データ

`Tests/Fixtures/bincue/`（`generate.py`、`manifest.json`）。既存 fixture の rr-joliet.iso（xorriso 製、38 sector、
Rock Ridge + Joliet、symlink）と pure150.iso（newfs_udf 製 UDF 1.50）を Python で sector に包んだ。

| fixture | 並び | 備考 |
| --- | --- | --- |
| mode1.bin | 2352、Mode 1、user data @16 | trailer 0 |
| mode1-garbage.bin | 同上 | EDC / ECC 位置に乱数（trailer を読まないことの証明） |
| mode2-subheader.bin | 2352、Mode 2、8 byte sub-header、user data @24 | sub-header は `00 00 08 00` ×2 の固定値 |
| mode2-plain.bin | 2352、Mode 2、user data @16 | ECMA-130 の Mode 2（2336 byte user data）の先頭 2048 byte |
| mode1-2448.bin | 2448、Mode 1 | 各 sector の後ろに 96 byte の乱数 |
| mode2-2336.bin | 2336、user data @8 | sync / header 無し |
| udf-mode1.bin | 2352、Mode 1、UDF 1.50 | 生 sector 上の pure UDF → `.udf` |
| mode1-truncated.bin | mode1.bin の末尾 100 byte 欠け | 最後の sector の trailer だけが無い |
| mode1.cue、multi.cue | cue sheet | 引用符あり LF、および audio track の後に `C:\IMAGES\...` の Windows path を CRLF で |

生成時に `unwrap()` が各 image から user data を取り出して元 image と byte 一致することを確認する。EDC / ECC は
書いていない（0 または乱数）ので、これらは user data の写しの fixture であって有効な CD sector ではない。

## 残る制約

- 実物の BIN/CUE（PSX、PC-98 など）は手元に無い。sector 配置は ECMA-130 の仕様と自作 wrapper の往復で確認した
  もので、独立 reader との照合は無い。実物が得られれば `kaito sha` と展開結果を bchunk などと照合する余地がある。
- EDC / ECC は検証しないので、壊れた sector は ISO 9660 / UDF 側の検査（extent、CRC を持つ構造）に掛からなければ
  そのまま通る。
- image の先頭 sector を ISO の LBA 0 と見なす。pregap（cue `INDEX 00`）や先行 audio track を同じ file に含む
  image は検出されない（cue の `INDEX` / `PREGAP` は読まない）。
- Mode 2 Form 2（2324 byte user data。PSX の `.STR` など）は先頭 2048 byte しか見えない。audio track、多 session、
  `.ccd` / `.sub` / `.mds` / `.nrg` / `.cdi` は対象外。cue の `FILE` は最初の data track だけを開く。
