## 1. LZMA core

Changed: `Sources/KaitoKit/Codecs/LZMA/LZMADecoder.swift`.

The existing implementation already keeps scalar range/model/window state in
local cursors and uses validated unsafe probability/dictionary storage. Replacing
class properties with locals again would not address the remaining hot path.

existed but could not be examined). Instruments first aborted on its unwritable

As a fallback, a diagnostic dylib collected 1 ms `ITIMER_PROF` interrupted PCs
inside the baseline process. A signal handler saved PCs; post-run `dladdr`, `nm`
and Swift demangling attributed them to **our binary**. `otool` inspection also
read only our generated code. Sampling overhead/kernel samples are not used as
an I/O estimate. These function-level observations are less powerful than an
Instruments profile:

| Input | Baseline samples | Findings |
|---|---:|---|
| Color | 4,350 | New-match run 1,802; literal run 686; short-copy helper 560; grouped-copy helper 125; main read 102; repeated-match helper 76 |
| JPEG | 2,846 | Literal run 1,479; new-match run 115; short-copy helper 18; main read 10 |

`libswiftCore` had four color and one JPEG samples. There was no evidence that
retain/release or exclusivity dominated. Normalization is inlined in the tree
loops; refill/outer LZMA2 work was not a separate dominant function. Assembly
exposed repeated shift/conversion range checks in literal context calculation,
short-copy calls, and per-match loads/stores through the grouped window cursor.

Changes:

- Advance a local input pointer; compute the committed input position at the
  boundary. Compare against the valid-input end directly for overrun.
- Use validated-width wrapping shifts and truncating position-state conversions.
  In particular, widen the previous byte to UInt64 before shifting by 8 for lc=0.
- Hoist the literal-model allocation base and pass a context-relative model
  pointer to the existing looped literal tree.
- Inline the existing short-copy helper. Keep grouped-copy scalars in locals,
  transferring them to the window around the existing boundary/overlap slow path
  and at group completion.

The probability arithmetic, normalization rule, child preloading, symbol order,
256-match run/drain boundary, failure precedence, and pending-match behavior stay
the same. The shared power-of-two `LZWindowCopy` primitive is not substituted for
LZMA's existing copy: retained LZMA dictionaries can have arbitrary lengths and
the decoder flushes contiguous dictionary spans. Existing LZMA copy semantics and
its exhaustive copy tests remain applicable.

Unsafe bounds are written beside the changes:

- Input cursors start within valid input; a symbol consumes at most 48 bytes and
  the allocation has the existing 64-byte sentinel. Overrun is checked at the
  existing symbol/run boundaries before a result is accepted.
- Literal contexts are below `2^(lc+lp)`, whose full model allocation is checked
  at initialization. Plain-tree indices are 1...255 and matched indices at most
  767 within each 768-entry model.
- Group count is at most the allocated 32 entries, initialized and distance/size
  validated by the unchanged run decoder. Fast copies check both contiguous
  dictionary spans, caller capacity and the existing overlap conditions. Cursor
  scalars are committed before any wrapping/partial slow copy.

The 7z factory opts into `streamsFirstUnit`. The consumer creates/reads unit 0
itself, with at most `workerCount - 1` later jobs ahead during this phase. On
completion it consumes later results through the original ordered worker path.
Other callers retain their existing default. Worker submission hooks now see
`unitCount - 1` jobs for a fully consumed 7z stream.

The consumer's unit retains the same conservative full-unit reservation, in
addition to the existing spare replay reservation. Worker count, maximum-unit
budget calculation and later-unit replay policy are preserved. Abandonment and
errors release the consumer reservation as well as worker/current/spare state.
Reads still fill at most 256 KiB across reset boundaries and throw away a failing
read's partial result, preserving the original externally returned prefix.
The new destination slice has `written <= capacity <= buffer.count` documented
beside its construction.

## 3. Header-only scan I/O and the 0.16 latency windows

Changed: `Core/ByteReader.swift`, `Codecs/LZMA/LZMA2ChunkHeader.swift`,
`LZMA2Decoder.swift`, `LZMA2TimedScanSource.swift`, and the
`SevenZipLZMA2ResetIndexTests`, `SevenZipInputLatencyTests`,
`SevenZipScanProbeTests` test files.

The scan reader has four bytes of storage and a one-byte normal read-ahead limit.
After the control byte, the shared parser explicitly prefetches two raw-size
bytes or four compressed-size bytes. A compressed property byte is still read
after dictionary-reset validation. This gives two reads for an ordinary compressed
chunk, three when it carries properties, two for a raw chunk, and one for end.
No request includes payload bytes.

The staging preserves validation order. Raw dictionary validation precedes raw
size reads; compressed sizes precede dictionary validation; properties follow it.
Both compressed sizes are fixed-width values whose derived lengths necessarily
satisfy their existing size checks. Batching them cannot bypass an earlier
size error. Short reads fall back to the scalar refill path. The prefetch raw
slice has a written `retained + requested <= count <= buffer.count` proof.

The initial batching change incorrectly kept these budgets per **physical read**.
That preserved artificial per-read traces but tightened the policy on media with
one cold read per header and warm follow-ups. The previous claim that this kept
the latency decision unchanged was wrong.

The correction sums the physical-read latency of each completed header, then
weights that single header sample by its **old** read count: raw 3, LZMA without
properties 5, LZMA with properties 6, end 1. A header occupies that many slots in
the calibrated windows; its summed cost goes in the first slot, with zero cost
in the remaining slots. Decisions are made at header completion, before reset
observations or payload seeks. Batching and all physical read ranges stay intact.

This preserves the decision policy, **not physical read counts**. In the model
with one cold read of latency L and zero-time warm follow-ups, the weighted
header is exactly the old one-byte cadence. The short 16-slot window still drops
the two largest costs, and the delayed-stall/raw-mean windows still span 256 old
read slots with their original 96 ms / 128 ms budgets. Simply changing to a
16-header trimmed average would change the short threshold; weighting the window
span retains the original outlier behavior as well. Actual nonzero warm-read
latencies are included in the header sum. The sum saturates at 128 ms + 1 ns to
avoid overflow while retaining the abort decision for extreme delays.

`SevenZipScanProbeTests` includes an independent legacy evaluator that actually
reads one byte per call and calculates the original windows from array slices.
It compares both completion and the exact aborting header against the corrected
batched scanner. For each header kind, five values around each threshold include
one nanosecond below, exactly at, and one nanosecond above the boundary:

| Header kind | Old read weight | Short-window cold threshold (12-header burst) | Raw-window cold threshold (300 headers) |
|---|---:|---:|---:|
| Raw | 3 | 1.750000 ms | floor(128 ms / 86) = 1,488,372 ns |
| LZMA without properties | 5 | 3.500000 ms | floor(128 ms / 52) = 2,461,538 ns |
| LZMA with properties | 6 | 7.000000 ms | floor(128 ms / 43) = 2,976,744 ns |

The raw thresholds include finite-window alignment (ceil(256 / weight) cold
reads); the five-read average is approximately 2.5 ms/header. Short bursts keep
the raw/stall totals below budget, while raw-boundary cases stay below the short
threshold and 4 ms stall floor, so the two threshold tests exercise distinct
policies. Another matrix covers NAS-like L = 1.0, 1.4, 2.0, 2.4, 2.5, 2.9, 3.0,
3.4 and 3.5 ms for all three header kinds. All 57 old/new comparisons agree.
A separate test verifies that warm follow-up time is added rather than discarded.

The existing injected-latency tests now describe **per-header** cold, sparse and
delayed patterns. They retain isolated-stall tolerance, dense/sparse aborts,
rolling-window checks, cached decisions, deferred first-page scanning and observed
backward restarts. They assert header-level decisions and coverage; physical
read counts are checked only for I/O reduction and absence of repeat scans.

`testContinuedCompressedHeadersUseTwoReadsPerChunk` still checks every read range
of a valid 681-chunk stream: **3,407 -> 1,364 calls (-60.0%)**, zero payload bytes
read by the scan, and successful full decoding afterward. The compressed-reset
fixture checks 19 -> 10 reads; raw scan tests check 3N+1 -> 2N+1. Short-reading
sources and malformed reset headers retain their existing fallback/precedence
tests. Correction commands and results are recorded at the end of this report.
