| design | 実装・コメント（file:line） |
|---|---|
| D0 | `ZstdBitReader.swift:76` / `:93` / `:98`：frame 所有、遅延確保、要求で開始・倍増、前 8 / 後 32 byte のみ padding 初期化。`ZstdFrameDecoder.swift:86` は全 scratch capacity と Huffman array capacity の和。 |
| D1 | `ZstdBitReader.swift:304` の into read：先読みを消費、大きな残りは直接 short-read loop、小さな残りは 4 KiB 先読み。範囲超過は read 前、0 / 負数 / 過大な返却長は truncated。 |
| D2 | `ZstdFrameDecoder.swift:188` / `:193`：RLE は size+32 の fill、raw は block の view。`ZstdHuffman.swift:109` は従来アルゴリズムの into wrapper。 |
| D3 | `ZstdFrameDecoder.swift:103` / `:272` / `:376`：`outputSlack = 32`、storage はゼロ化せず、余白を読まない・数えない・返さない・hash しない。 |
| D4 | `ZstdSequenceTable.swift:1` / `:27` / `:75`：8-byte cell、kind ごとの遅延 allocation、正規化分布を直接 spread → state に変換。53 Int の scratch は next-state カウンタにも再利用。predefined は immutable static arrays。 |

| D6 | `ZstdFrameDecoder.swift:284` / `:294` / `:301` / `:315` / `:345` / `:376`：class property を hot loop に持ち込まない。コピー前に literal / output / history の順で拒否。16 / 8-byte match chunk は現在位置より前だけを読む。offset<8 は実長以内の最初の byte copy と周期の倍数を使う。 |
| D7 | `ZstdFrameDecoder.swift:232`：frame 所有 input / literal / cell pointers を渡し、完了まで寿命を保持。sequence count 0 は literal を storage にコピーする。 |
| D-T | `ZstdSequenceTable.swift:98`：instance tuning、default / 8-byte / byte-then-period の match 経路。Huffman tuning は次段階用。 |
| D8–D11 | この round は未実装。 |

Bulk memmove の閾値は追加していない。history compaction の既存 memmove は維持。
小さい match の byte prefix は `min(8, length)` で止め、余白から読み戻さない。

エラー差分：従来の sequence 内の `zstd bitstream underflow` は padded refill の同じ throw、
または最後の `zstd sequence trailing bits or literals` で検出する。
`zstd repeat offset is zero` は offset guard の `zstd match exceeds history` に統合。
`zstd repeat offset` は正の OF 基底により到達不能。assert 済みメッセージ・KaitoError・checksum 検証は維持。

  の 56 extra bits（第 2 refill）を検査し、OF30 の履歴拒否で保持量が変わらないことも確認。

- T6：Huffman jump table、FSE descriptions、sequence 先頭末尾 8 byte の全 bit、他の 256 sample bits。
  5,291 mutations、最大 sequence count と極短 stream の各拒否 < 1 s、通常 build 全体 < 30 s。
- T7：0…4 KiB の 500 独立 frames、3 levels、checksum / content size の有無を交差。
  expectedSize 付き Decompressor、scratch <= 64 KiB / storage <= maximumBlockSize+32 を毎 read 確認。
- T8 は Stage 2。T9 の既存テストは保持（T5 の ceiling と helper 引数追加を除く）。

## Round 2 / Stage 2 の実装と不変条件

G1 通過後、Stage 1 の snapshot を `.build/p11/stage1-source/`、従来の結果を
`.build/p11/stage1-logs/` に保存した。before / stage1 binary は再作成も上書きもせず、両 SHA-256 と
inbox の両 hash を再照合した。Stage 1 の sequence loop、sequence table builder、FSE、Decompressor、
XXH64 の実装は維持する。Frame の差分は Huffman object の再利用と tuning / padded output の受渡しだけ。
既存 padded reader には Huffman 用の peek / drop だけを追加した。

| design | 現行の実装・コメント（`Sources/KaitoKit/Codecs/Zstd/` 以下） |
|---|---|
| D0 / D8 | `ZstdHuffman.swift:2`, `:16`, `:99`：frame 所有の class、初回必要時だけ single table 4 KiB と workspace 448 B を確保。2-byte cell の上限 2,048、重み 256 B、rank count/start 各 12 Int。deinit で解放し全体のゼロ埋めをしない。 |
| D8 | `ZstdHuffman.swift:68`, `:107`：weight の count → rank start → 各記号の範囲を fill。単記号表の再構築には一時配列、filter / enumerated / append、追加 allocation が無い。既存の重み・深度・総和・deepest rank・個数検証を維持する。 |
| D8 optional | `ZstdHuffman.swift:139`：重みの FSE table / checked reader は既存実装を維持。任意の D4 builder への置換は実施せず、測定なしの追加最適化を行わない。 |
| D9 | `ZstdHuffman.swift:114`, `:167`, `:214`：新表で pair 有効フラグと累計を reset、割当は保持。type 3 はどちらも保持。今回 section を足した累計が T 以上になった decode だけで pair を構築。累計の整数 overflow は saturate、Int.max tuning は構築しない。pair capacity は 4 KiB から必要量で倍増し上限 16 KiB。 |
| D8 / D9 lifetime | `ZstdFrameDecoder.swift:204`：frame に一つの Huffman object を遅延生成、type 2 は同じ object に readTable、type 3 はそのまま参照。 |
| D10 reader | `ZstdBitReader.swift:149`, `:155`：peek / drop は検証済み batch / tail 用。Stage 1 の load 境界と refill / read arithmetic は変更しない。 |
| D10 batch | `ZstdHuffman.swift:236`, `:254`, `:280`：全 stream の bit 数と segment 出力余地から最小 K。pair は L=4 / 最大48 bits / 8 output bytes、single は L=5 / 最大55 bits / 5 bytes。各反復の refill 後は最低57 bits。mask が表の範囲を保証し、lookup ごとの分岐・throw は置かない。 |

| D10 tail | `ZstdHuffman.swift:344`：同じ padded reader の remaining で pair / single tail を処理。stream 前の byte は lookahead から除外して0補完、実符号長 <= remaining を検査。各 stream の exact end を維持。 |
| D0 / D10 pad | `ZstdHuffman.swift:304`：有効出力の直後32 bytesだけ0にする。Array API は count+32 を一度確保する薄い wrapper、本番は frame の literal scratch に直接書く。 |
| D-T | `ZstdSequenceTable.swift:98`：pair threshold と fast-loop flag を frame→Huffman に接続。mutable global / 新規 Sendable 回避属性 / public API は無い。 |

## Round 3 / Stage 3 の実装

D11のみ実装。Stage 2 source/test snapshotは `.build/p11/stage2-source/`、当時の7 threshold binariesは
`.build/p11/stage2/threshold-binaries/` に保存した。before / Stage 1 / Stage 2 binaryは再作成・上書きせず、

仕様の6 seedsだけを使い、他のscratchpad資料や外部decoder実装を読んでいない。

`nextBlock` / `compressedBlock`はstorageの実byteだけの`UnsafeRawBufferPointer`を返す。
raw blockはD1の既存into readで直接storageへ、RLEは直接fillする。`storeBlock`とblock返却Arrayを除去した。
raw/RLEは`Checked.add`とcontent-sizeを確保前に検査し、空blockはprepareBlockしない。
空RLEでもそのbyteは消費する。XXH64のstripe / tail算術は変更せず、raw-buffer入口を追加して
従来のArraySlice入口をwrapperとした。Decompressorはviewを全て消費した後だけクリアし、次blockの復号や
frame解放へ進む。最後のcontent-size / checksum検査はview返却前に完了する。

`ZstdBitReader.swift` / `ZstdFSE.swift` / `ZstdHuffman.swift`はStage 2とbyte-identical。
sequence実行・match copy・literal/Huffman/tableの解析もStage 2と一致する。
V8の終了時にT=32768へ復元し、`ZstdSequenceTable.swift`全体もStage 2と同一になった。
D12の任意read-ahead変更は計測・実装とも行っていない。
