# brotli（`.br` / `.tar.br` / `.tbr`）の読み取り追加（2026-09-20）

環境: macOS 27.2 / Apple Silicon / brotli CLI 1.2.0（Homebrew）/ Apple Compression
（`COMPRESSION_BROTLI`、macOS 12 以降。SDK の `compression.h` は「decoder は任意 level を復号」と記す）。

## 実装と範囲

- 公開 `ArchiveFormat` に `.brotli`（raw value `"brotli"`）を追加。単一 stream `.br` と、名前が
  `.tar.br` / `.tbr` の圧縮 tar を読む。
- `BrotliStreamHeader` が RFC 7932 §9.1 の可変長 WBITS（10〜24）と RFC 9841 §6 の large window
  形（`00010001` + 6 bit、10〜62）を LSB 先頭で解釈し、window `(1 << WBITS) - 16` を
  `ReadLimits.maxDictionarySize` と照合する。bit 7 が立つ `0x91` は RFC 9841 §8.1 の shared brotli
  framing 署名で `unsupportedMethod`。
- 復号（`BrotliDecompressor`）は `XZDecompressor` と同じ Apple Compression の streaming wrapper。
  brotli には連結・padding の規定が無いので END 時点で入力が残っていれば `malformed`。Apple の
  decoder は入力を先に全部消費して出力を小分けに返すことがあるため、入力が尽きた後も FINALIZE
  付きで呼び続けて END まで出力を引き出す（この点は XZ wrapper と異なる）。切り詰められた stream
  では Apple の decoder が最後の入力を OK で受け取った後、入力の無い FINALIZE 呼び出しで ERROR を
  返し、破損では入力が残っている呼び出しで ERROR を返す（黒箱で観察）ので、入力が尽きた後の空呼び出し
  での ERROR だけを `truncated`、それ以外の ERROR を `malformed` にする（gzip / xz と同じ区別）。
- 検出: magic が無いので `.br` / `.tbr` の名前、有効な header、先頭 64 KiB の試し復号（END の後に
  入力が残る stream は不採用）がそろったときだけ `.brotli`。window が辞書上限を超えるものは
  試し復号せずに形式だけ認め、open で `limitExceeded` にする。名前の無い Data は受理しない。
  署名を持つ形式（ZIP など）が `.br` を名乗っても署名が勝つ。
- サイズと checksum は形式に無い（`uncompressedSize == nil`）。破損は Apple の decoder が error を
  返す範囲でしか検出できない。
- `ArchiveFormat` の網羅的 switch を持つ利用側には、新しい case の追加が必要。

実装入力は RFC 7932 §9.1 / §1.5.1、RFC 9841 §6 / §8.1（`inbox/brotli/rfc7932.txt`
`394abd1879e016f4eac89512c2acaf92f7b2d67feb8ab58b6b118c213be07146`、`rfc9841.txt`
`88711e3f33ad7e3e9e7f1c35b60cd8c85095bfe7fab9555dcc9154caa0537042`）、Apple Compression の
公開 API、既存 `XZDecompressor` である。google/brotli を含む第三者実装の source は開いていない。

## 独立した検証データ

`Tests/Fixtures/brotli/`（`generate.py`、`manifest.json`）: project-owned の text / 構造化 binary /
乱数 8 KiB / 空 / 1 byte / USTAR tar を brotli CLI 1.2.0 で `-q 1` / `-q 5` / `-q 11`、
`-w 10` / `-w 16` / `-w 17`、`--large_window=30` で圧縮した 11 本。すべて同 CLI の `-d` で復号して
原本と一致することを確認してから保存した。header の先頭 byte（`8f` / `1f` / `a1` / `e2` / `81` /
`11` / `3f` / `0f`）も manifest に記録し、テストで WBITS の解釈と照合する（large window の 2 byte 目
`1e` はテスト側の固定値）。64 KiB の試し復号と 256 KiB の入力 chunk をまたぐ stream（乱数英数字
300,000 byte + ほぼ縮まない乱数 300,000 byte、-q 5 で約 500 KB）は fixture に収まらないため、
brotli CLI があるときだけテスト実行時に生成する（CI は `brew install brotli` と
`KAITO_REQUIRE_BROTLI=1` で skip を許さない）。

## 残る制約

- Apple Compression が RFC 9841 の large window をどの WBITS まで復号するかは Apple の実装依存で、
  WBITS 30 までは実測で復号できた。上限内でも decoder が `COMPRESSION_STATUS_ERROR` を返せば
  `malformed`。
- 試し復号は 64 KiB までなので、それより後ろで壊れた `.br` は open 後の読み取りで失敗する。
  RFC 9841 §7 の shared dictionary 依存 stream（framing 無し）は RFC 7932 と byte 上区別できず、
  辞書参照が 64 KiB より後ろなら検出を通って読み取りで `malformed`（または別の出力）になる。
- 出力サイズが不明なため、`maxEntrySize` などは読み取り中に適用される（gzip / xz と同じ）。
