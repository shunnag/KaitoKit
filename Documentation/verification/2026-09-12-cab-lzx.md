# CAB LZX 検証記録（2026-09-12）

対象: `feat/cab-lzx`、bd `cooViewer-c1vj.5`。作業ツリー上で検証し、commit / push は行っていない。
実装は `Sources/KaitoKit/Codecs/LZX/` と CAB reader の decoder 選択。
MSZIP は `CabFolderDecoder` への適合だけを追加し、復号処理を変更していない。

## 出自

ローカルの Microsoft [MS-PATCH] v20160613 と [MS-CAB] v20110304、利用者提示の
CAB/LZXD 差分十一項目、既存 KaitoKit の実装を参照した。
PDF / 全文テキストの SHA-256 と差分の全項目は [design.md §10](../design.md#10-出自プロベナンスと参照の規則) に記録した。
インターネットは使用していない。

libmspack / cabextract、7-Zip / p7zip、XADMaster、The Unarchiver、Wine cabinet.dll、
ms-compress、libfwnt、およびその他の LZX 実装 source は開かず、検索・参照・引用していない。
`/opt/homebrew/bin/cabextract` 1.11 は展開の black-box oracle としてだけ実行した。
実 CAB の内容もバイト列の比較だけに使用し、実行ファイルを実行していない。

`Scripts/fixtures/make-cab-lzx.py` は Python 標準ライブラリだけの自作 encoder / CAB writer。
2-byte hash chain による greedy LZ77、最大 257 byte の一致、頻度から作る静的 Huffman、
長さが 16 を超える場合の頻度順平衡木への制限、pretree の delta / 17 / 18 / 19、
三 block type、E8 前処理、CFDATA checksum を実装した。
検証用の一時 CAB を cabextract で展開し、名前の集合と全ファイルの元バイト列が一致してから
保存先へ書く。一致しない出力を fixture として採用する経路はない。

## Oracle による解釈の確認

| 実験 | cabextract 1.11 | 採用した規則 |
|---|---|---|
| main tree に長さ 1 の要素を一つだけ置く | decompression error、終了 1 | singleton を拒否。二つの非零要素から完全な木を作る |
| 使わない length tree を全ゼロにする | 元入力と一致、終了 0 | 空 length tree は許可し、使用時には malformed |
| 使わない aligned tree を全ゼロにする | decompression error、終了 1 | aligned tree は空でも拒否 |
| raw header 前の padding を 1〜16 bit 全て作る | 全 16 folder が一致 | 既に word 境界にあっても 16 bit 消費する |
| block が複数 frame を跨ぐ / frame 境界で終わる | 一致 | CFDATA 終端でビットだけを整列し、木・block 残量・辞書・R0〜R2 は持ち越す |
| 65,537 byte の raw block | 一致 | raw bytes と末尾の奇数 padding を frame 越しに処理する |

拒否された二実験は `--probes` の一時ファイルであり、保存 fixture には含めない。
プローブ結果は `manifest.json` の `probes` にも記録した。

破損検証は固定全件の CFDATA 25 / 50 / 90% / 最後の 1 byte での切断、各 24 箇所の
bit 反転（14 × 24 = 336）、各 folder 最終 frame の直接切断を含む。
window bits 14 / 22 など、block type 0 / 4〜7、block size 0 / folder 残量超、
入力が尽きる前後の block サイズ不一致、余剰 word、Kraft 違反、長さ 16 の decode fallback、
pretree 17 / 18 / 19 の範囲超過と不正 delta、履歴超過、block / frame を超える match、
不正 raw R0 / padding を検査した。全て想定した `KaitoError` で停止し、crash / hang はない。
チェックサムを除いた直接復号のテストもあり、checksumMismatch だけで検査を済ませていない。

## 敵対レビュー追補

2026-09-12、利用者からの 5 レンズの敵対レビューで確定した minor 2 件を修正した。同一 folder の後方
seek は旧 decoder を nil にしてから構築し、辞書二つの一時的な同時保持を避ける（初期化が throw
すれば stream も throw し、次回再構築する）。最後の CFDATA の `cbUncomp == 0`、または NEXT_CABINET
がある最後の folder を継続と判定して decoder に伝え、継続時だけ cabinet 内の総展開量に対する block
宣言上限と folder 完了検査を省く。全 frame が 32,768 byte である規則、split CFDATA 自体の拒否、
continued file の unsupportedMethod は維持した。cabextract より厳格な四点（pretree run の overshoot、
継続しない folder の末尾 block の過大宣言、folder 末尾の奇数 raw block の pad 欠落、最終 frame 末尾の
余剰 16-bit word）は仕様準拠として据え置いた。`verbatim-w15` の最後の CFDATA を圧縮 byte の前半だけ・
`cbUncomp == 0` にし、次巻名 / disk 名と NEXT_CABINET、最後の file の `iFolder = 0xFFFE` を設定した
回帰標本で、全非 continued file の SHA-256 一致と continued file の拒否を確認した。split のみ / flag
のみの判定と後方読みも検査する。cabextract 1.11 はこの小型標本では次巻不足によって先頭側も失敗する
ため、oracle 比較には同じ非 continued payload を保ち、継続 file に 1 frame を足した literal 版を
自作 encoder の部品から作成した。完全版を cabextract で検証してから同じ split 加工を施し、cabinet 1
単体の全非 continued file が cabextract と KaitoKit で一致した（次巻不存在の警告はあるが終了 0）。
追補後の `swift build` は警告なし、`CabLZXTests` 17 件と既存 `CabReaderTests` 13 件、計 30 件は失敗 0。

> **Adversarial review follow-up (2026-09-12).** Fixed the two confirmed minor findings from the
> user-provided five-lens review: release the old dictionary before rebuilding on backward seeks,
> and pass folder continuation state through to the decoder so cabinet-local sizes do not constrain
> continuing block declarations or trigger folder completion checks. Full frames, rejection of split
> CFDATA and unsupported continued files are preserved. Four stricter-than-cabextract checks remain
> specification-compliant: pretree run overshoot, oversized final blocks in non-continuing folders,
> missing odd raw-block padding at folder end, and an extra 16-bit word after the final frame.
> The exact compact regression fixture passes KaitoKit; cabextract 1.11 fails on its missing next cabinet.
> The oracle comparison therefore also uses a literal variant with identical contained files and one
> extra frame in the continued file. After verifying the complete archive, the same split transformation
> produces a standalone cabinet 1 whose contained files match in both decoders. The build has no warnings,
> and all 30 CAB tests pass.
