## 独立検証(orchestrator による再実測)

### fixture

素材は 5 member: `a.txt`(6)、`b.txt`(19)、
`a-very-long-member-name-exceeding-sixteen-chars.txt`(17。**16 文字超**)、
`exactly16chars.o`(17。**ちょうど 16 文字**)、`data.bin`(30,000)。

| fixture | 生成 | 名前の格納方式 |
|---|---|---|
| `bsd.a` | macOS `ar -qcS` | BSD。`#1/52` + データ先頭 52 byte |
| `gnu.a` | GNU binutils 2.47 | 同上(host 設定のため BSD 形式)|
| `sysv.a` | **自作**(System V ABI / ar(5) の仕様のみ)| SysV。`//` 表 + `/<10進オフセット>` |

### symbol table member の扱い(方針を途中で訂正した)

当初は symbol table を隠す設計にしたが、**訂正して公開する**ようにした。

`withsym.a` で XADMaster が `__.SYMDEF SORTED`(40 byte)を entry として返すことを
実測し、家の流儀と照合し直した結果である。tar の pax 拡張ヘッダを隠すのは正しい
——あれは中身が次の entry の metadata として吸収される符号化の産物で、隠しても情報が
失われない(pax 形式の tar で両エンジンとも隠すことを実測で確認した)。しかし
`__.SYMDEF` は**どこにも吸収されない独立した member** で、隠すとその byte 列が完全に
失われる。正典のツール `ar -t` も一覧に出す。

したがって:
- **公開**: `/`(SysV symbol table)、`/SYM64/`、`__.SYMDEF`、`__.SYMDEF SORTED`、
  `__.SYMDEF_64` 系
- **隠す**: `//`(長名表のみ。他 member の名前解決に消費されるため pax ヘッダと同性質。
  XADMaster の出力にも現れない)

`#1/` の解決を symbol table 名の判定より**先に**行う順序は維持している。
`__.SYMDEF SORTED` は 16 文字かつ空白を含むため macOS は `#1/20` 形式で書き、
名前を復元しないと判定できないからである。
