# HTML Help（CHM / ITSF）の読み取り（2026-09-21）

環境: macOS 27.2 / Apple Silicon / 7-Zip 26.03 `7zz`（黒箱 reader。CHM は読めるが書けない）。

## 裁定

候補調査（[2026-09-20-format-candidates.md](2026-09-20-format-candidates.md)）の裁定 1「GPL / GFDL ライセンスの
文書を入力に使ってよいか」を利用者が 2026-09-21 に「良いです」と認めたので、Wise / Wing の GPL 文書を入力に含めた。

## 実装と範囲

- 公開 `ArchiveFormat` に `.chm`（CLI の `detect` は `chm`、compat は `CHM`）を追加。検出は offset 0 の `ITSF` と
  version 2 / 3。
- `CHMReader`（`Sources/KaitoKit/Formats/CHM/CHMReader.swift`）: ITSF header（header section table の 2 項目、
  version 3 の content offset）→ ITSP directory header → PMGL listing chunk を first から next 連鎖で辿り
  （PMGI index chunk は読まない。chunk 数と訪問数で循環を止める）、ENCINT の名前長 / 名前（UTF-8）/ section /
  offset / 長さを読む。`::DataSpace/NameList` から section 名、`::DataSpace/Storage/<name>/ControlData`（`LZXC`、
  version 1 / 2、reset interval、window size）、`…/Transform/{7FC28940-9D31-11D0-9B27-00A0C91E9C7C}/InstanceData/
  ResetTable`（entry 数、展開後 / 圧縮後長、0x8000 block、各 block の圧縮側 offset）、`…/Content` を読む。
- 公開する entry: `/` で始まる利用者 file（`#SYSTEM` `$FIftiMain` などの format file を含む）。名前末尾 `/` は
  directory。`::` の内部 file は出さない（7-Zip の一覧と同じ集合）。method は section 0 が `stored`、
  MSCompressed が `LZX`、ControlData が `LZXC` でない section の file は `unknown`（読むと `unsupportedMethod`）。
  `formatSpecific` に `section` と `sectionName`、`solidGroup` に section 番号。
- LZX: 既存 `LZXDecoder`（[MS-PATCH] の CAB bitstream）を reset interval（group）ごとに新しく作り、group 内の
  block を reset table の範囲で `decodeFrame`（0x8000 出力ごとに 16 bit 境界）する。出力は 0x8000 の倍数
  （末尾は padding）。直近 1 group の展開結果を lock 付きで cache し、file 単位の random access に応える。
  window は ControlData の値（version 2 は 0x8000 block 単位）から `windowBits` を求め、`maxDictionarySize` と照合。
  reset interval は window 以下（または 4 MiB 以下）に限る。
- 検査と上限: 各 offset / 長さは file と section の大きさで、directory は `maxMetadataSize` と
  `maxMetadataRecordCount`、entry は `maxEntryCount` / `maxPathComponentCount` / `maxEntrySize`、名前は空要素・`.`・
  `..` を拒む。reset table が section を覆わなければ `malformed`、content が欠ければ `truncated`。
- fuzz: `Scripts/fuzz/mutate.py` に CHM の LZX section を見つける locator、`make-compressed-seeds.sh` に basic.chm を
  seed として追加。

黒箱で確定した点（Russotto の記述の確認を含む）:

| 点 | 確定した内容 | 方法 |
| --- | --- | --- |
| reset interval の意味 | LZ window・Huffman 木・repeated offset・E8 変換位置を含む全状態を捨て、E8 header bit から読み直す | 実物 2 本を 7-Zip と一致させた。E8 有効の自作 fixture（reset ごとに位置 0 から変換）を 7-Zip が正しく展開 |
| block 境界 | 0x8000 の出力ごとに 16 bit 境界（CAB の frame と同じ）、reset table の offset がその圧縮側位置 | 同上 |
| 末尾の padding | 最後の block も 0x8000 まで符号化されている（block header の宣言サイズが 0x8000 の倍数） | 実物 2 本 |
| 内部 file の見え方 | 7-Zip は `::DataSpace/…` を出さず `/` 以下の全 file（`#`/`$` を含む）を出す | 実物 2 本の一覧 |
| ITSF version 2 | Russotto の配置（content offset field 無し、directory の直後が content）で書いた自作 file を 7-Zip は "Is not archive" と拒む | 自作 file。version 2 は reader で受理するが未検証 |

## 残る制約

- ITSF version 2 は Russotto の記述どおりに読むが、実物も 7-Zip が受理する自作 file も無く未検証。
- PMGI index chunk は使わず全 PMGL を読む（一覧目的には十分。名前検索の高速化はしない）。
- `#SYSTEM` などの format file の中身（title、default topic、`#STRINGS`）は解釈しない。`::DataSpace/…` は公開しない。
- LZXC version 1（byte 単位の reset / window）は仕様どおり受理するが標本が無い。reset interval が window より大きく
  4 MiB を超える file は `unsupportedMethod`（cache の上限）。
- 実物は日本語 HTML Help 2 本だけ。大きな CHM（数十 MB、reset table の entry 数千）での速度は未計測。
- 名前に空の要素や `.` / `..` を含む entry があると書庫全体を `malformed` で拒む（CFB のように置き換えない）。
