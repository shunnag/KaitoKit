# reader の送信と親ディレクトリ権限の検証（2026-09-10）

## 1. 変更範囲

KaitoFinder 向けの追加機能を 0.3.0 として CHANGELOG の先頭に記録した。
直近の 0.2.0（`7b8c508`）と同じく、バージョンは CHANGELOG の節で更新する。

- 公開 `ArchiveReader.reopen()` の戻り値に `sending` を追加し、別の isolation domain
  へ送信できることを doc comment に明記した。Swift 6 の検査で独立性を呼び出し元まで
  伝えるため、内部の `RAR4Reader.reopened` / `RAR5Reader.reopened` の戻り値にも
  `sending` を追加した。3 メソッドとも処理本体は不変。他の公開 API は変更していない。
- `FileByteSource.openDescriptorAnchoredToParent` 内で親の open が `EPERM` / `EACCES`
  のときだけ、同じ読み取り専用フラグで葉を直接 open する。両方の入口
  （公開 initializer と `openAnchored`）がこの経路を共有する。`fstat`、通常ファイルの
  検査、失敗時の descriptor 解放は共通の既存処理をそのまま使う。
- 内部の directory anchor を optional にし、RAR locator は anchor がない場合に
  匿名 origin を保持する。後続巻は既存の
  `unsupportedMethod("multi-volume from Data")` となる。通常経路の `openat`、
  anchor の保持、初巻の同一ファイル検証、後続巻の no-follow 制約は変えていない。

> **Scope**
>
> The additive KaitoFinder capabilities are recorded as 0.3.0 at the top of CHANGELOG,
> following the version-section convention used by 0.2.0 (`7b8c508`).
> `ArchiveReader.reopen()` now returns `sending ArchiveReader` and documents transfer to another
> isolation domain. The two internal RAR reopen methods also need `sending` to propagate that
> independence through Swift 6 checking. All three method bodies remain unchanged; no other public
> API changes. Parent-open `EPERM` / `EACCES` alone enables direct leaf opening inside the shared
> helper. Existing descriptor validation and cleanup remain shared. Missing anchors produce an
> anonymous RAR origin and the existing continuation error. Normal anchoring, identity checks,
> `openat`, and no-follow constraints remain unchanged.

## 2. 新規 XCTest

`Tests/KaitoKitTests/FileByteSourcePermissionTests.swift` に次の 5 件を追加した。
入力は既存のクリーンルーム builder（`ArArchiveBuilder` / `RAR5TestSupport`）で生成する。

| テスト | 検証内容 |
| --- | --- |
| `testExecuteOnlyParentOpensArchiveAndPublicFileByteSource` | 小さな ar を一時ディレクトリに書き、chmod `0o111` 後の親 open が実際に `EACCES` になることを確認。URL で一覧・内容を読め、公開 initializer でも全 byte が一致し、anchor は nil |
| `testReadableParentRetainsWorkingDirectoryAnchorForRARVolumes` | 読める親の anchor が非 nil であり、その anchor から第 2 巻を解決。公開 reader も第 2 巻の entry を一覧・読み取りできる |
| `testExecuteOnlyParentReportsUnsupportedMultiVolumeRAR` | 同じ権限制限で、提供 source を使う locator と URL から直接開く locator の両方が後続巻に既存の unsupportedMethod を返す。公開 reader のエラーも確認 |
| `testMissingParentPreservesENOENT` | 公開 initializer と URL reader の両方で、親が無い場合の ENOENT が保持される |
| `testReopenedReaderCanBeSentFromActorToExtractionWorker` | actor が保持する reader を reopen し、Task.detached へ渡して内容を読む。元の actor の reader も引き続き読める |

権限制限テストは skip せず、親 open の失敗を明示的に assert する。
teardown はテストの成否にかかわらず chmod `0o700` で復元してから削除する。
`EPERM` はこの chmod テストでは発生させておらず、catch 条件の確認で検証した。

> **New XCTest coverage**
>
> Five tests in `FileByteSourcePermissionTests.swift` use existing clean-room builders.
> They cover an execute-only parent with an asserted real EACCES failure, successful archive listing
> and byte reads through both public entry points, nil fallback anchors, working normal RAR sibling
> resolution, the existing unsupported continuation error through both locator construction paths
> and the public reader, unchanged ENOENT, and transfer from an actor to a detached extraction worker
> while retaining use of the original reader. Permission tests do not skip. Teardown restores mode
> 0o700 before removal even on failure. EPERM is covered by inspection of the catch condition, not
> generated by the chmod test.

## 3. 実行環境とコマンド

Apple Silicon（arm64）、macOS 27.0（26A5425a）、Apple Swift 6.4
（swiftlang-6.4.0.33.1）。Package.swift は従来どおり Swift 6 language mode、macOS 26.0 以上。
依存の追加・変更はない。

指定コマンドは両方実行したが、ホーム配下の module cache への書き込み制限により
manifest のコンパイル段階で終了値 1 となった。

```sh
swift build 2>&1 | tail -20
swift test 2>&1 | tail -40
```

```sh
set -o pipefail
CLANG_MODULE_CACHE_PATH=/tmp/kaitokit-module-cache swift build --disable-sandbox 2>&1 \
  | tee /tmp/kaitokit-2026-09-10-build-adjusted.log | tail -20
CLANG_MODULE_CACHE_PATH=/tmp/kaitokit-module-cache swift test --disable-sandbox 2>&1 \
  | tee /tmp/kaitokit-2026-09-10-test-adjusted.log | tail -40
git diff --check
```

> **Environment and commands**
>
> Apple Silicon arm64, macOS 27.0 (26A5425a), Apple Swift 6.4 (swiftlang-6.4.0.33.1).
> Swift 6 language mode and the macOS 26.0 deployment target are unchanged; no dependencies changed.
> Both requested commands were attempted and exited 1 during manifest compilation because the
> home-directory module cache is not writable. The adjusted commands above use a writable temporary
> module cache and disable SwiftPM's own sandbox while retaining the execution environment's
> filesystem restrictions. Pipefail checks the actual exit status; tee preserves complete logs.
