# RAR4 unpack version 20 / 26 の実装と検証 — 2026-11-02

`cooViewer-c1vj.9`。RAR4 container のうち version 20 / 26 の圧縮 entry を展開できるようにする。
version 15 と custom RAR VM は今回も対象外。

## 仕様と実装

- [RAR 1.5-4.x format notes](https://github.com/bitplane/rar-research/blob/master/doc/RAR15_40_FORMAT_SPECIFICATION.md) §16-17 と、
  RAR 2.50 / UNRAR 7.23 の black-box 入出力を使用した。第三者の decoder source は参照していない。
- version 20 と 26 は同じ decoder 系で、26 は大きな file 向けの互換宣言とする。1 MiB 窓、
  298 / 48 / 28 の Huffman 表、version 20 の repeat-distance ring、長さ bonus、
  1〜4 チャンネルの音声予測と表の再読み込みを実装した。
- solid は window・Huffman 表・repeat distance・音声状態を member 間で共有する。後続 member の
  先頭で必ず新しい表を読まず、`isSolid` と `tablesWereRead` で継続を判定する。
- `RARSolidCoordinator` は形式ごとの allocationSize を使う。RAR20 は固定 1 MiB、
  RAR29 / RAR5 は従来の allocationWindowSize を維持する。
- truncated 入力・無効な Huffman code・match distance over history は構造化された error にし、
  zero パディングを有効な出力として受理しない。

## 実書庫と fixture

公式の `https://www.rarlab.com/rar/rar250.exe` から UNRAR で取り出した RAR 2.50 を、
一時領域の DOSBox-X で実行して自作した。入力と出力は UNRAR 7.23 で全 byte が一致した。
生成コマンド・入力・期待 SHA-256 は [fixture の説明](../../Tests/Fixtures/rar20/README.md) を参照。

- `autorej.rar`: 通常 LZ、2,300 byte。
- `audio.rar`: `-mm` の音声ブロックを含む、32,768 byte。
- `biglz.rar`: 長い LZ、163,840 byte。97 byte buffer で match の続きを再確認。
- `solid.rar`: 2 member の順読み・逆順読み。
- version 26 宣言: `autorej.rar` の UNP_VER と header CRC を変更した書庫。UNRAR 7.23 も同じ出力を確認。

取得元の fixture に明示的な再配布ライセンスがなかったため、最初に比較用として使った
bitplane の書庫は checked-in fixture に含めず、すべて自作した RAR 2.50 書庫へ差し替えた。
1 / 3 / 4 チャンネルの独立した実書庫は今回の検証範囲外。2 チャンネルの実音声ブロックは一致した。
