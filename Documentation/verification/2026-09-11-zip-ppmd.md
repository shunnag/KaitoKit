## 実装と出自

追加した codec は `PPMdVarISuballocator.swift`、`PPMdVarIModel.swift`、
`PPMdVarIRangeDecoder.swift`、`PPMdVarIDecoder.swift` の 4 ファイル。
ZIP dispatch で二バイトの little-endian parameter word を分離し、既知サイズを渡す。
order 1 と restore 3 は malformed、辞書上限は arena 確保前に確認する。
model は指定個数の symbol で停止し、最後の EOF escape を読まず arena を解放する。
サイズ不明の ZIP entry は malformed とする。method 93 / 95 / 96 は従来どおり未対応。
既存の未対応 method テストから 98 だけを除き、PPMd7 ファイルは変更していない。

一次資料は利用者提供の `inbox/ppmdi1/`（Shkarin var.I rev.1、2002-04-28）と
同梱 `APPNOTE-5.10-method98.txt`（PKWARE APPNOTE §5.10）だけ。
原典 URL は <http://www.compression.ru/ds/ppmdi1.rar>。

- 取得物 SHA-256: `5a559300c26949fc5dd015983bfe680fd9a32c2b4afb85320dc9b38f90f8c5d6`
- Model.cpp: `6548d0be2c4b88f07a75f774f2990ffcbb45e72ed091b3a14389cc76bb4cee9e`
- SubAlloc.hpp: `c2b8759bd2d4194554ac42e6a2aaa48a78c75ef90fd7394fa705c2502947338c`
- Coder.hpp: `2532e1ede8ad3e7d066bbbd6adc3d9478a6eb043e509f2a455a6e237f5060971`

原典の “Written and distributed to public domain by Dmitry Shkarin” 宣言を確認した。
Coder.hpp は同梱の Dmitry Subbotin による公開ドメイン carryless range coder。
既存 KaitoKit の PPMd7 / RARPPMdRangeDecoder は arena offset と streaming 入力の設計例に使用。
Web、7-Zip / p7zip、XADMaster、The Unarchiver、libarchive、pyppmd、その他実装 source は
開いていない。今回の method 98 fixture / matrix では 7zz バイナリを圧縮 writer としてだけ使い、
期待値は圧縮前の project-owned payload から計算した。

> The port uses only the supplied public-domain Shkarin reference and APPNOTE §5.10.
> No other implementation source or Web page was consulted. Existing KaitoKit code supplied
> design patterns. Method 98 verification uses 7zz only as a black-box writer and checks original inputs.

## 固定 fixture

`Scripts/fixtures/make-zip-ppmd.py` は Python 標準ライブラリと 7zz を使う。
seed は `0x50504D49`。以下の 7 本、合計 10 entry を登録した。

| fixture（`.zip.b64`） | 元入力サイズ | 実際の order / memMB / restore | base64 bytes |
| --- | ---: | --- | ---: |
| text-o8-default | 32,768 | 8 / 1 / 0 | 2,246 |
| text-o2-mem1m | 32,768 | 2 / 1 / 0 | 4,394 |
| text-o16-mem1m | 32,768 | 16 / 1 / 0 | 2,270 |
| binary-o6-mem4m | 262,144 | 6 / 4 / 0 | 35,627 |
| random-o16-mem1m-restart | 57,344 | 16 / 1 / 0 | 27,246 |
| random-o16-mem1m-cutoff | 57,344 | 16 / 1 / 1 | 26,849 |
| mixed | 32,790（4 entry の合計） | stored、8 / 1 / 0、空 stored、空 PPMd | 2,643 |

すべて 40 KB（40,000 bytes）以内である。期待 SHA-256 / CRC32 / サイズは
[manifest.json](../../Tests/Fixtures/zip-ppmd/manifest.json) とテスト内の定数に記録した。
一覧の名前・サイズ・CRC32・methodDescription を確認し、通常 read、reopen 後の read、
37-byte chunk の EntryStream で全 entry の SHA-256 を比較する。

text の既定オプションは `-mm=PPMd`。7zz は小さな入力の辞書を自動縮小するため、
実際のヘッダは 1 MiB だった。4 MiB を記録させる binary fixture は構造化 32 KiB を
8 回反復した 256 KiB とした。generator は method 98 と各 parameter field を検証する。

当初の一様乱数 24 KiB と反復末尾では復元が起きなかった。
採用した乱数入力は、一様乱数 12 KiB の列を 2 回並べ、反復 payload 32 KiB を続ける。
Store への切替を防ぎ、高次数 context を増やすことでメモリ枯渇を実際に発生させた。
同一入力の復号と SHA-256 一致に加え、以下のカウンタを確認した。

```text
random-o16-mem1m-restart: restart=1, cutOff=0
random-o16-mem1m-cutoff:  restart=1, cutOff=2
```

7zz は空 entry を method 0 で書いた。mixed の empty-ppmd.bin は
parameter `0x0007` と任意の 4-byte stream を持つ size 0 / CRC 0 の entry として合成した。
既知サイズが 0 なので range coder を初期化せず空 Data を返す。

## 生成 matrix と破損入力

matrix は order `{2, 4, 8, 16}` × 指定メモリ `{1m, 16m}` × restore `{0, 1}` ×
入力 `{text 64 KiB, structured binary 64 KiB, uniform random 32 KiB, repetitive 128 KiB}`
の **64 書庫**。`SevenZipTestSupport.requireSevenZip()` で writer 不在時だけ skip する。
全 entry の read が圧縮前の Data と一致した。48 書庫が method 98、16 書庫の一様乱数は
7zz が stored に切り替えた。PPMd の乱数・復元検証は上記の固定 fixture で別に保証する。
小さい matrix 入力では `mem=16m` も実際のヘッダで 1〜2 MiB に縮小される。
16 MiB を確保する長大な writer 入力の行列を検証したという意味ではない。

破損入力テストは以下を確認した。

- 圧縮 stream の 25% / 50% / 90% / 最後の 1 byte を切断し、元の宣言圧縮サイズを保持した
  ZIP が truncated / malformed / checksumMismatch のいずれかで拒否される。
  25% / 50% / 90% は宣言サイズを実際の短い圧縮サイズに合わせても decoder が拒否する。
- stream の 16 等分位置で 1 byte を反転し、復号エラーまたは CRC mismatch を確認する。
- order 1 / restore 3 は malformed。memMB 2 と辞書上限 1 MiB は limitExceeded。
  memMB 256 は既定上限内で実際に model を生成し、初回 symbol を復号して arena を解放する。
- compressedSize 0 / 1 は truncated。restore 0 / 1 / 2 の空 entry は空 Data を返す。
- central directory の展開サイズを +1 にした ZIP を拒否する。
  decoder に直接 expectedSize +1 を渡す検証でも root EOF escape で truncated となる。
- prefix / suffix を持ち、最大 3 bytes しか返さない ByteSource と 1-byte 出力読みでも一致する。
  source は呼出側の要求範囲が圧縮範囲を超えていないことも検証する。
- restore 2 のパラメータで、復元前までの正常 stream が一致することと、メモリ枯渇を起こす
  ヘッダ変更入力が freeze 分岐を通り、復号エラーまたは CRC mismatch で終わることを確認した。

末尾 EOF escape のみを削り、宣言圧縮サイズまで整合するように書き換えた場合、
既知サイズの全出力と CRC が一致すれば受理することがある。これは指定された
「ちょうど uncompressedSize 個で止め、EOF escape を読まない」動作による。
未使用の EOF byte の存在を検証する目的で追加復号は行っていない。
切断の最後の 1 byte の検証は、元の圧縮サイズを保持した物理的切断の検証である。

## 未検証の範囲

- 正常な freeze(2) 符号化書庫との一致。7zz の `-mm=PPMd:o=16:mem=1m:a=2` は
  exit 2 / `E_INVALIDARG` で失敗することを writer として実測した。
  freeze の model / removeBinConts / 内部状態 FREEZE+1 は移植したが、分岐到達と
  robustness の検証を正常ストリームの互換性確認として扱わない。
- PKZIP / WinZip の実機 writer による生成物、x86_64 / 物理 Intel の実行、専用 sanitizer run。
  method 98 の同じ APPNOTE / var.I rev.1 仕様として実装した範囲であり、未実施の writer 検証を
  実施済みとはしていない。
- 大きな writer 入力での 16〜256 MiB 各辞書の網羅。256 MiB はパラメータ受理・確保・初回
  symbol 復号を確認し、固定 fixture の最大実辞書は 4 MiB である。

> Valid freeze-encoded archives remain unverified because the available 7zz writer rejects `a=2`.
> PKZIP/WinZip-generated archives, x86_64 and a dedicated sanitizer run were not tested.
> Small matrix inputs cause 7zz to reduce dictionary sizes; the maximum full fixture dictionary is
> 4 MiB, while the 256 MiB parameter, allocation and first symbol were checked separately.
> The declared-size decoder intentionally does not validate unused EOF-escape bytes.
