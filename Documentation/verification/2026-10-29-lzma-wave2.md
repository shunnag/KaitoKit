## Instruction-level findings

`otool -tvV W/bin/head` inspected only our release executable. `nm -n` followed
by `swift demangle --compact` identified the two hot functions. Addresses below
are from this exact baseline binary; counts are dynamic instructions along the
stated path, not estimated cycles or micro-ops.

| Path | Without normalization | With normalization | Counting boundary |
|---|---:|---:|---|
| Plain literal, each of the first seven bits | 25 | 29 | `0x100050030..74`, then `0x100050014..2c`; normalized path additionally `0x100050078..84` |
| Plain literal, final bit | 16 | 19 | `0x100050088..c0`, then `0x1000500d0`; normalization adds `0x1000500c4..cc` |
| Matched literal, prefix still equal | 24 | 27 | `0x10004ff94..d8`, then `0x10004ffe8..ffc`; excludes final exit / mismatch transfer |
| Matched literal, plain suffix after mismatch | 19 | 23 | `0x1000501d0..20c`, then `0x1000501c4..1cc`; normalization adds `0x100050210..21c` |

The seven-bit plain loop's 25 instructions decompose into three child-address /
load instructions, fifteen range/probability/normalization-test instructions,
and seven symbol/child-selection/register-transfer/loop instructions. The final
stage avoids child preloads. The eight plain-tree bits therefore take 191
instructions without normalization, excluding initialization and the per-byte
literal-run bookkeeping. These are aggregate paths; the actual input changes
normalization frequency.

The ideal dependency chain needs a probability load, `range >> 11`, multiply,
comparison, probability update/store, symbol shift, and conditional normalization
(plus range/code subtraction for a one bit). A single-outcome branch-based
sketch can omit the other outcome's arithmetic, but ignores branch prediction
cost. Here LLVM already emits conditional selects: both probability-update
candidates, two subtractions, one comparison and four `csel`s, with no hand-coded
mask decoder. Of the plain loop's 25 instructions, the fifteen-instruction
range kernel contains no bounds, ARC, or scalar-state memory traffic to remove.
Its child preloads deliberately trade extra loads for a shorter dependency chain.

Concrete observations:

- Both loops keep range/code in 32-bit registers and input in a pointer register.
  Probability loads/stores are `ldrh` / `strh`, from one contiguous allocation
  with constant model offsets. These suggested optimizations already exist.
- The literal function has zero calls and zero `brk`s. There are no per-bit
  bounds checks, retain/releases, exclusivity calls, or class-field reloads.
  Widening probability loads is free in `ldrh`; X-register symbol arithmetic
  does not imply a separate conversion instruction.
- The literal run does reload mask / shift / model-base values from its stack
  once per byte because of register pressure. These are not per-bit field loads.
  Scalar coder/window state is committed at the run boundary, not each bit.
- Normalization is `lsr #24; cbnz` over the three-instruction refill sequence.
  It is already one conditional branch, but the no-normalization path takes it.
  Trial N reverses that layout with a branch likelihood hint.
- Child selection repeats the range comparison after normalization, and the
  plain loop transfers the new code register each iteration. These account for
  two real instructions, but are not bounds checks or ARC overhead.
- The new-match function has two static calls, both to the existing group-copy
  helper, and two traps outside its bit kernels: a signed-to-unsigned generated
  count conversion and the direct-bit-count range guard. Neither trap was removed.
  Reverse-tree result shifts also have dynamic Swift shift-width handling.
- State transitions already use comparisons/arithmetic, not lookup tables.
  Retaining the match-run drain/validation boundaries preserves error precedence.

## Independent attempts

Each patch starts from HEAD, without stacking the others. Rejected patches are
retained under [`Tests/Measurement/lzma-wave2/attempts`](../../Tests/Measurement/lzma-wave2/attempts).

| ID | Change | Release assembly result |
|---|---|---|
| N | `_slowPath(range < rangeTop)` in normalization | Plain common path still 25 instructions, with `cbz` to refill; literal function 296 → 301 static instructions, new-match 894 → 929 |
| S | Wrapping distance-prefix shift, proven count 1…30 | No instruction reduction: three instructions merely reordered; literal 296 / new-match 894 remain unchanged |
| M | One matched-literal loop with `offs`, shifted match byte, and decoded-bit arithmetic | Literal function 296 → 271 static instructions, but matched loop 24 → 25 dynamic instructions before normalization; plain suffix also executes the extra mask bookkeeping |
| R | Wrapping reverse-tree result shifts, proven counts 0…4 | Removes dynamic shift-width handling from that loop; new-match function 894 → 890 static instructions; literal function unchanged |

For M, `offs` is 256 until a mismatch and zero thereafter. The model index is
`offs + (matchByte & offs) + symbol`, where `symbol` is 1…255: at most 767 in
the existing 768-entry model. Once `offs` clears, the same loop visits the plain
suffix indices in exactly the original order. For R, distance slots come from
a six-bit tree; the position-model path uses at most five reverse bits and
alignment uses four. Neither patch changes the input sentinel, overrun checks,
validation order, or output commits.
