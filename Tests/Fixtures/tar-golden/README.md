# Tar public-value golden

Frozen from `24311ac` before changing `Sources` for S12 / P3-K stage A.
The corpus contains 109 inputs: eight existing tar fixtures, eleven supplied
GyoshukuKit / third-party fixtures, and 90 synthetic structure/framing cases.
The manifest records SHA-256 of every decoded input. The golden covers 2,868
input / opening / option combinations, compared with recording both off and on.

S12 correction 1 changes storage and loading only. Every decoded input and the
expected JSON retain their original bytes and SHA-256. `TarGoldenInputSupport`,
the framing encoder, opening modes, public rows, summaries and comparison
expressions are unchanged. The separate SPI option helper is a no-op on the
baseline checkout.

## Compact storage

`public-values.json.lzfse` stores the original 24,492,114-byte JSON in 103,945 bytes,
using Foundation's `NSData.compressed(using: .lzfse)`. Tests decompress it with
Foundation, independently of KaitoKit's codecs, and assert the decompressed
SHA-256 from `public-values.json.sha256` before reading the JSON:

`9ea2ba84246f423558a82207b23052d94db06ac03a61b14ef6f926c1c339f796`

107 inputs remain frozen base64 files. Two deterministic inputs are constructed
at test time from the manifest's versioned recipe and seed. `generated/` is a
logical path with no committed archive. Both use the **original input SHA-256**,
asserted by every `TarGoldenCorpus.decoded` call, including layout/map/fuzz tests.

| Input | Recipe / seed | Generated bytes | SHA-256 |
| --- | --- | ---: | --- |
| many-entries | many-entries-v1 / 0 | 72,704 | `119a0633a25d888de51ac59de13ae6a7e87bbb270de3b987f90d6523e458905c` |
| gzip-rich-header | gzip-rich-header-v1 / 65 | 270,300 | `ec0a0f961ca86b286539cb763716f64548fa321eb869c37676c1fdb29c1677a1` |

`many-entries` uses the existing tar builder for `f0`–`f69`, with one body byte
`seed + index` each, mode 0644 and Unix time 1700000000. `gzip-rich-header` uses
the original FEXTRA/FNAME/FCOMMENT/FHCRC header, a 270,000-byte comment repeating
the seed byte, and its computed header CRC. Its original 270-byte deflate/trailer
tail is frozen as base64 in the recipe; tests do not re-encode it with a potentially
different zlib version. Seeds select byte patterns rather than a random generator.

## Compare and dump readable JSON

Normal tests verify every input hash and compare all original public values with
recording off and on. All opening methods, four option modes, reopen checks,
read/stream digests and byte lengths remain covered. Summaries over 64 entries
retain the full-row SHA-256 and the original first/last rows. Dates are compared
when the current time zone has zero GMT offset.

Run from the repository root (use writable SwiftPM cache paths if needed):

```sh
TZ=UTC swift test --filter TarPublicValueGoldenTests
swift test --filter TarPublicValueGoldenTests
TZ=UTC KAITOKIT_DUMP_TAR_GOLDEN="${TMPDIR:-/tmp}/tar-golden-readable.json" swift test --filter TarPublicValueGoldenTests
shasum -a 256 "${TMPDIR:-/tmp}/tar-golden-readable.json"
```

The dump command writes the decompressed frozen JSON and still runs every normal
comparison. Failures preserve all full actual rows under
`$TMPDIR/kaitokit-tar-golden-actual/all-rows.json`. A stored-value mismatch also
writes `expected.json` and `actual.json` in the same directory. Outside UTC,
`actual.json` retains the expected `utcValues`, which are not compared in that run.

```sh
diff -u "${TMPDIR:-/tmp}/kaitokit-tar-golden-actual/expected.json" "${TMPDIR:-/tmp}/kaitokit-tar-golden-actual/actual.json"
```

## Regenerate on the baseline only

Use a `24311ac` checkout with these fixtures, the Step-0 test support/dependencies
and the no-op option helper. Do not regenerate expectations from the changed parser.

```sh
git diff --quiet -- Sources
TZ=UTC KAITOKIT_WRITE_TAR_GOLDEN=1 KAITOKIT_DUMP_TAR_GOLDEN="${TMPDIR:-/tmp}/tar-golden-regenerated.json" swift test --filter TarPublicValueGoldenTests
shasum -a 256 "${TMPDIR:-/tmp}/tar-golden-regenerated.json"
```

Regeneration writes `.json.lzfse` and `.json.sha256`; compare the readable dump
with the original JSON using `cmp`. `KAITOKIT_WRITE_TAR_GOLDEN_INPUTS=1 swift test
--filter TarPublicValueGoldenTests` is the original Step-0 input-generation command.
It now writes recipes for the two deterministic inputs. Do not regenerate the
remaining frozen inputs during normal verification; native encoders or external
tools may produce different bytes in another environment.
