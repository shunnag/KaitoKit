# Apple Disk Image（UDIF）と HFS+ の読み取り（2026-09-22）

環境: macOS 27.2 / Apple Silicon / hdiutil（黒箱 writer、`hdiutil attach` が真値）/ 7-Zip 26.03 `7zz`（黒箱 reader）。

## 実装と範囲

- 公開 `ArchiveFormat` に `.dmg`（CLI の `detect` は `dmg`、compat は `Apple Disk Image`）を追加。検出は file 末尾の
  `koly`（UDIF）を、単一 file の圧縮形式（bzip2 / xz / gzip の magic は UDIF の最初の chunk にも現れる）より先に見る。
  koly が無い生 image は GPT / Apple Partition Map / bare の位置に HFS+ の volume header があれば `.dmg`。
- `UDIFDiskByteSource`（`Sources/KaitoKit/Formats/DMG/UDIFImage.swift`）: koly（version 4、data fork offset、XML の
  位置と長さ、sector 数）→ XML plist（`PropertyListSerialization`）の `resource-fork/blkx` → 各 `mish`（start sector、
  entry 数、40 byte の chunk entry: 種別、sector、sector 数、data offset、data 長）。chunk を disk 順に並べ、重なりを拒み、
  隙間は 0 として読む。種別: zero-fill（0）、raw（1）、ignore（2、0 として読む）、zlib（0x80000005、既存
  `DeflateDecompressor`）、bzip2（0x80000006）、lzfse（0x80000007、Compression framework）、lzma（0x80000008。hdiutil
  の ULMO は xz container なので既存 `XZDecompressor`）、comment / terminator は読み飛ばし、ADC（0x80000004）と未知の
  種別は読むときに `unsupportedMethod`。1 chunk の展開後は 64 MiB まで、直近 4 chunk を lock 付きで cache。
- `DMGReader`: volume の候補 = disk 先頭（bare volume）、GPT の entry（sector 1 の `EFI PART`、entry LBA / 数 / size）、
  Apple Partition Map（sector 1 の `PM`、`pmPyPartStart`）、UDIF の各 blkx の開始 sector。最初に HFS+ / HFSX の
  volume header（offset 1024、`H+` v4 / `HX` v5、block size は 2 の冪）が見つかった volume を公開する。HFS+ が無ければ
  ISO 9660（`CD001`）/ UDF（`BEA01`）の volume を既存 reader に渡し、`NXSB`（APFS）は名前付きで `unsupportedMethod`。
- `HFSPlusVolume`（`HFSPlusVolume.swift`）: volume header の fork data → catalog B-tree（header node の node size、
  first leaf、葉を fLink で辿る。record offset 表と key 長を検査、key 後の pad byte）→ folder / file record（thread は
  読まない）。extents overflow B-tree は葉を全部読んで (fileID, forkType) → 追加 extent にする。fork の読み取りは
  catalog の 8 extent + overflow を volume の block 位置に写し、連続する範囲をまとめて `ByteRunDecompressor` で返す。
- `HFSVolumeListing`: root（ID 2）から folder を辿って path を組む。`\\0\\0\\0\\0HFS+ Private Data` と
  `.HFS+ Private Directory Data\\r` は出さない。file は `HFS+ (stored)`、hard link（fdType `hlnk` / creator `hfs+`、
  special = link reference）は `iNode<n>` の fork を本文にして `formatSpecific["hardLink"]`、symbolic link（mode
  S_IFLNK）は `.symlink` + `linkTargetStoredAsData`（data fork が path）、resource fork があれば
  `name/..namedfork/rsrc`（`fork=resource`）、UF_COMPRESSED（ownerFlags 0x20）の file は
  `HFS+ compressed (decmpfs)` で size 不明・読むと `unsupportedMethod`。更新日時は contentModDate（1904 起点 UTC）、
  permissions は fileMode の下位 12 bit、非零の type / creator は `macType` / `macCreator`、`volumeName` は root の名前。
- 上限: XML と B-tree の読み取り量を `maxMetadataSize`、entry 数 / 深さ / 各 fork の size を `maxEntryCount` /
  `maxPathComponentCount` / `maxEntrySize`、chunk の展開量は固定 64 MiB。
- fuzz: `mutate.py` に koly → blkx から圧縮 chunk を探す locator、`make-compressed-seeds.sh` に hfs-zlib.dmg を追加。

黒箱で確定した点（hdiutil の出力）: ULMO の chunk は xz container（magic `FD 37 7A 58 5A 00`）、UDBZ の chunk は `BZh`、
blkx の `Name` と `CFName` は空、hdiutil create の partition 表は GPT（HFS+ partition は sector 40 から）、UDRO でも

## 通過した検証

- `DMGReaderTests` 3 件、失敗 0: 4 圧縮 image の検出・形式・file / directory の集合（symlink、resource fork、decmpfs を
  含む）・サイズ・SHA-256・method 名・日時・`volumeName`、symlink の本文 = target、permissions 0755、hard link の
  `formatSpecific`、resource fork entry、49 extent の file を 3,000 byte buffer で読む、`reopen()`、1 byte ずつ返す
  source、raw image、UDIF 内の ISO、ADC / APFS の名前付き拒否、koly の version 違い → `unsupportedMethod`、koly 署名
  破損 → `unsupportedFormat`、plist 破損 → `malformed`、chunk data 破損 → 失敗、`maxEntryCount` / `maxMetadataSize`。
- `KaitoArchiveDMGTests`（compat: formatName、directory、fork、link）、`CLISmokeTests.testDetectAndListDMG`。
- 既存 ISO / UDF / 検出 / 単一 file suite が通過（検出順の変更後）。全 suite（0.8.0 の release 直前の working tree）:
  KaitoKitTests 1344 件 / skip 45 / 失敗 0、KaitoKitCompatTests 34 件 / 失敗 0。
- ASan mutant fuzz: hfs-zlib / lzfse / lzma / raw を seed に 400 mutant、CI と同じ seed script（dmg-zlib.dmg を含む
  21 seed）で 63 mutant、いずれも crash 0 / hang 0 / sanitizer 0。

## 残る制約

- ADC（UDCO）chunk、APFS volume、decmpfs 圧縮 file の本文、暗号化 DMG（UDIF の外側の CEncryptedEncoding）、
  分割 DMG（`.dmgpart`）、sparseimage / sparsebundle は非対応。
- 複数の HFS+ volume がある disk は最初の volume だけ。directory hard link（`fdrp` / `MACS`）は空 directory として
  出し `directoryHardLink` を付けるだけ。
- 名前は catalog の UTF-16（Apple の分解形）のまま。
- koly の checksum（data / master）と blkx の checksum は検証しない。
- chunk cache は直近 4 個（hdiutil の chunk は 1 MiB。上限 64 MiB の chunk を書く writer では最大 256 MiB）。
- catalog / extents file 自身の extent は catalog record の 8 個 + extents overflow（catalog は ID 4 で参照）。
- decmpfs 圧縮 file は Apple 製 DMG（Icon Composer）では大半を占める。次の release の最優先候補。
- attributes B-tree（xattr）は読まない。7-Zip が出す `name:attr` entry は無い。
- extractor の既存方針により、絶対 path の symlink と、他の symlink を経由する target の symlink は作らない
  （Firefox の `/Applications` link、Electrum の 11 本）。
