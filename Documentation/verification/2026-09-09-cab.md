# CAB reader 検証記録(2026-09-09)

対象コミット: `efb978b`
実装: `Sources/KaitoKit/Formats/Cab/`(CabStructures / CabReader)、
`Sources/KaitoKit/Codecs/MSZIPDecompressor.swift`、`Sources/KaitoKit/Core/DOSTimestamp.swift`

## 1. 方法

XADMaster はブラックボックスの展開オラクルとしてのみ使う(design.md §10)。
CAB は XADMaster も CFFILE 順に同じ一覧を出すので、**順序込みの総合 digest を直接比較**できる。
fixture は `gcab` 1.6 で生成したもの 4 種と、gcab が書けない形を自作した 2 種。
自作分は XADMaster と `cabextract` 1.11 の 2 つのオラクルで裏を取った。

## 2. 形式の実測

すべて little-endian。

| 構造 | 長さ | 内容 |
|---|---|---|
| CFHEADER | 36 | `MSCF`、cbCabinet、coffFiles、ver 1.3、cFolders、cFiles、flags、setID、iCabinet |
| CFFOLDER | 8 + cbCFFolder | coffCabStart、cCFData、typeCompress |
| CFFILE | 16 + 名前 | cbFile、uoffFolderStart、iFolder、DOS date/time、attribs、NUL 終端名 |
| CFDATA | 8 + cbCFData + cbData | csum、cbData、cbUncomp(最大 32768) |

`typeCompress` は 0=None、1=MSZIP、2=Quantum、3=LZX。下位 4bit が方式で、
LZX は上位に window size を持つ。

flags 0x0004(RESERVE_PRESENT)が立つと `iCabinet` の直後に
cbCFHeader(u16)/ cbCFFolder(u8)/ cbCFData(u8)と abReserve が入り、
**以後 CFFOLDER が 8+cbCFFolder、CFDATA が 8+cbCFData バイトになる**。
0x0001 / 0x0002 は前後のキャビネット名を NUL 終端文字列で続ける。

ファイルは folder の連結された非圧縮ストリームの
`[uoffFolderStart, uoffFolderStart + cbFile)` を切り出したもの。

### MSZIP の落とし穴(この形式で最も間違えやすい点)

各 CFDATA は `CK` + **独立した raw deflate ストリーム**だが、
**LZ77 の履歴は folder 内の CFDATA をまたいで引き継がれる**。
ブロック *n* はブロック *n−1* の出力へ後方参照できる。
zlib では各ブロックごとに `inflateReset` した後、最初の `inflate` の前に
`inflateSetDictionary(直前までの出力の末尾 32 KiB)` を呼ぶ必要がある。
`CK` の 2 byte は inflate に渡さず読み飛ばす。履歴は folder 境界は越えない。

これを外すとブロック 0 は解けてブロック 1 で distance-too-far になる。
**単一ブロックの fixture では絶対に露見しない**ため、11 ブロックに分かれる
350,070 byte の `cab-multiblock.cab` を専用に作った。

## 3. 受け入れ測定

実装前ベースライン: 全 fixture が `Unsupported archive format`(pass=0 fail=6)。

| fixture | 由来 | entry 数 | 総合 digest | 判定 |
|---|---|---|---|---|
| cab-stored.cab | `gcab -c`(typeCompress 0)| 6 | 67c74a92c447fa8409d8dbadc0022ce8a7699be1a84109950f5e35d5240fad38 | 一致 |
| cab-mszip.cab | `gcab -c -z`(1 ブロック)| 6 | 同上 | 一致 |
| cab-reserve.cab | 自作(予約領域あり)| 6 | 同上 | 一致 |
| cab-next.cab | 自作(NEXT_CABINET)| 6 | 同上 | 一致 |
| cab-multiblock.cab | `gcab -c -z`(**11 ブロック**)| 2 | 4d50ab4313783770fdd5f88fde2461630bf9eede761f7969ad6993cc0cf9359d | 一致 |
| cab-utf8.cab | `gcab -c -z`(attribs 0x00a0)| 2 | 879d6c92f921852067aea0fe6c699e32370b6a2f06d2ebfa1a77aa7c2a18ac13 | 一致 |

pass=6 fail=0。stored / mszip / reserve / next が同一 digest を返すことで、
**予約領域の長さ加算とキャビネット名文字列の読み飛ばしがオフセットをずらしていない**ことも
同時に確認できる。`cab-multiblock` の 350,070 byte は 1.9ms で復号した。

### 自作 fixture の裏取り

`cab-reserve.cab` は `cab-mszip.cab` から予約領域(cbCFHeader=6 / cbCFFolder=2 / cbCFData=3)を
持つ形へ組み直したもの。自作 writer と自作 reader が同じ誤解をする循環を避けるため、
XADMaster と `cabextract -t` の両方が通常版と同じ内容を返すことを先に確認した。

## 4. 敵対的入力

| 入力 | 応答 | 時間 |
|---|---|---|
| `MSCF` 破壊 | unsupportedFormat | 0.2ms |
| cFiles = 0xFFFF | truncated(確保前に停止)| 0.2ms |
| cFolders = 0xFFFF | truncated | 0.2ms |
| coffFiles がファイル外 | truncated | 0.1ms |
| 名前が NUL で終わらない | truncated | 0.1ms |
| iFolder が範囲外 | malformed: cab folder index | 0.1ms |
| cbUncomp = 40000(> 32768)| malformed: cab block size | 0.2ms |
| uoffFolderStart が folder 外 | malformed: cab file extent | 0.2ms |
| payload 1 byte 反転 | 読み出し時に checksum mismatch | — |
| typeCompress = 3 | 一覧は成功、展開時に unsupportedMethod: cab LZX | — |
| typeCompress = 2 | 同上 cab Quantum | — |

CFDATA の checksum は 0(未計算)なら検証を飛ばす。`gcab` は非 0 を書く。

## 5. 対応範囲と、まだ対応していないもの

| typeCompress | 状態 |
|---|---|
| 0 None | 対応 |
| 1 MSZIP | 対応(folder をまたぐ辞書引き継ぎ込み)|
| 2 Quantum | 一覧のみ。`cooViewer-c1vj.6` |
| 3 LZX | 一覧のみ。`cooViewer-c1vj.5` |

多分割キャビネットは、`NEXT_CABINET` / `PREV_CABINET` が立っていても
**手元のキャビネットにあるファイルは通常どおり読む**(XADMaster の挙動を実測して合わせた)。
実際にまたぐファイル(`iFolder` が 0xFFFD 以上)だけを個別に
`unsupportedMethod("cab multi-cabinet set")` で拒否し、書庫ごとは拒否しない。
