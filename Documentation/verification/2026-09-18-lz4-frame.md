# LZ4 frame の読み取り追加（2026-09-18）

環境: macOS 27.2 / Apple Silicon / Xcode 27.0。macOS 26 と Intel の実行結果は含まない。

## 実装と範囲

- 公開 `ArchiveFormat` に `.lz4` を追加。単一ストリーム `.lz4` と、URL名が
  `.tar.lz4` の圧縮tarを読み取る。ファイル名がないDataは単一ストリームとして扱う。
- 現行frameの独立／連続block、最大64 KiB / 256 KiB / 1 MiB / 4 MiB、
  stored block、連結、skippable frame、宣言サイズとXXH32のheader/block/content checkを扱う。
- LZ4とZstandardはskippable magicを共有する。最初の通常frameまで本文を確保せずに移動して識別する。
  skippableだけの曖昧な入力は従来どおりZstandard。探索・frame・blockの件数には上限を適用する。
- 保持するのは最大1 blockずつの圧縮入力と展開結果、および最大64 KiBの履歴。
  一項目の上限・全項目の上限・メモリ読み出し上限、キャンセル、端数入力、末尾検査に接続する。
  圧縮tarの一時展開は既存の権限0600・作成直後unlinkの保存先を使う。
- KaitoFinderの関連付け・Finder Services・表示名・プレビュー経路へ接続した。
  単体とtar.lz4は読み取り専用とし、形式変換で複合拡張子全体を取り除く。
- **非対応**: legacy LZ4 frame、外部辞書、新規LZ4出力。辞書IDのあるframeはIDが0でも明示的に拒否する。
  LHAの `-lz4-`（stored）とは別の形式である。
- `ArchiveFormat` の網羅的switchを持つ利用側には、新しいcaseの追加が必要。

実装入力は [LZ4 Frame Format v1.6.4](https://github.com/lz4/lz4/blob/dev/doc/lz4_Frame_format.md)、
[LZ4 Block Format（2022-07-31）](https://github.com/lz4/lz4/blob/dev/doc/lz4_Block_format.md)、
[XXH32公開アルゴリズム v0.2.0](https://github.com/Cyan4973/xxHash/blob/release/doc/xxhash_spec.md)。
第三者codec実装ソースは参照していない。製品の読み取りは外部CLIを起動しない。

## 独立した検証データ

KaitoKitの `Tests/Fixtures/lz4-frame/generate.py` でプロジェクト所有の入力を生成し、
**LZ4 1.10.0 CLI** で圧縮・全byte展開を照合した10書庫をbase64で保持する。
最大4 MiB blockを越える入力、連続block、stored、空、checkなし、USTARを含む。
manifestは書庫と展開結果のSHA-256、サイズ、生成引数を記録する。

XXH32の固定12 vectorも、このCLIが出したcontent checksumから採った。
自前のchecksum実装から期待値を生成していない。

## 通過した検証

- LZ4専用 **11件、失敗0、skip0**。全fixtureのSHA、極小read、XXH32のstripe境界、
  全16 skippable magic、frame間の状態リセット、全切り詰め位置と各byteの破損、
  不正距離・長さ・終端、辞書、サイズ・件数上限、取消しを含む。
  メモリ／ディスクのtar staging、`.001`分割、unlink後のreopen、全memberのbyte一致も確認した。
- 検出変更後のZstandard等の選択検証 **31件、失敗0**（73.014秒）。
- KaitoKit全件 **1,187件、失敗0、skip45**（380.730秒）、Compat **24件、失敗0**。
  省略されたうち手元にある外部CAB・暗号化StuffItの2件は、環境変数を指定して別途成功した。
  CABの106 fileとStuffItの10書庫を照合。未実施の既知条件は43件。
- GyoshukuKit全件 **202件、失敗0、skip0**（509.402秒）。
  `GYOSHUKU_LARGE_TAR_TESTS=1` とし、4 GiB超の圧縮tar作成検証も含めた。
- KaitoFinder関連 **64件、失敗0、skip0**（17.336秒）。
  型宣言、設定、作成、LZ4の単体／tarのプレビュー用ファイルのSHA、読み取り専用判定、
  先頭skippable frameがある圧縮tarの原本保持と変換名を確認した。
- ASan/UBSan: 6 seedから **240変異、crash0・hang0・診断0**。
  圧縮payload範囲を必須とし、checksumなしのseedも含めた。
  正常10 fixtureも同じsanitizerビルドでSHA一致・診断0。
  SwiftPMの出力先は `--show-bin-path` から取得する。過去のアーキテクチャ別pathを固定しない。

## メモリ

KaitoFinderの `Tools/benchmark_lz4_memory.py` で、実KaitoKit CLIの各実行を
`/usr/bin/time -l` により測定。最大4 MiB block、XXH32付き、独立／連続の両方式。
入力生成と公式CLIによる圧縮は測定対象プロセスに含めず、各展開結果のSHAを元入力と照合した。
今回はDebug CLIのRSSであり、Releaseの速度やアプリ全体のRSSを表すものではない。

| 入力 MiB | 独立block peak RSS MiB | 連続block peak RSS MiB |
|---:|---:|---:|
| 16 | 22.16 | 22.27 |
| 64 | 22.16 | 22.27 |
| 256 | 22.17 | 22.28 |

256 MiBのSHA-256: `dc461ea2a1cb36572be9f627fa094960f160f3b0a5d6c66a730b9559f27f3c76`。
128 MiBのRSSゲートは6条件すべてで通過。
