# RAR 1.3 / 1.4 の旧暗号と comment の検証

対象: cooViewer-c1vj.12。stored・圧縮の旧暗号、暗号化 solid、packed archive comment、
stored file comment を実装する。

## 入力資料と fixture

- [RAR 1.3 / 1.4 format notes §7-8](https://github.com/bitplane/rar-research/blob/master/doc/RAR13_FORMAT_SPECIFICATION.md)
  の 3-byte key・減算 stream、固定 comment key `Key = [0, 7, 77]` を使う。
  第三者の decoder source は参照していない。
- `Scripts/fixtures/make-rar13-crypto.py` が暗号化通常・solid・comment の fixture を生成する。
  UNRAR 7.23 の password 展開と `unrar v` の comment 表示を照合した。
- 実 RAR 1.402 の `README_password=password.rar`、`STOREPWD.RAR`、`COMMENT.RAR`、`FCOMM.RAR`
  を `KAITOKIT_RAR13_FIXTURES=<repo>/inbox/rar13` で比較した。git には含めていない。

## 実装で確定した規則

- password から key を作り、byte ごとに `Key1 += Key2`、`Key0 += Key1` として ciphertext から
  `Key0` を引く。archive comment は固定 key、file comment は raw OEM text。
- `RAR13EncryptedByteSource` は各 read の offset まで keystream を再計算するため、random access と
  暗号化 solid の後方読みができる。entry ごとに新しい key を使う。
- password が無ければ `passwordRequired`、誤っていれば `wrongPassword`。password を正しく変更した
  後は solid state も再構築する。旧形式の password byte は現時点で ASCII に限定する。

## 確認した結果

- `RAR13ReaderTests`: **13 tests / 0 failures**。
  - checked-in の暗号化 stored・圧縮で、password 未指定・誤り・正しい値への変更と全 byte 一致。
  - 暗号化 solid の順読み・逆順読み・再読が一致。
  - 自作 comment と実 RAR 1.402 の packed archive comment・stored file comment が一致。
  - 実 RAR 1.402 の暗号化 stored・圧縮が UNRAR 出力と一致。
  - `passwordProvider` は 1 回の解決を以後の entry に再利用し、非 ASCII password は拒否。
  - 既存の通常・solid・checksum・切断・不正 header 検査にも退行なし。
- `RAR15DecoderTests`: **7 tests / 0 failures**。
- ASan 付き CLI（`swift build --scratch-path .build/rar13crypto-asan --sanitize=address --product kaito -j 4`）
  で実 RAR 1.402 の暗号・comment、自作暗号化 solid・comment を展開。
  変異した ciphertext 256 件も **sanitizer finding / crash / hang / 誤った正常出力 0**。
- Release CLI（`swift build -c release --scratch-path .build/rar13crypto-release --product kaito -j 4`）
  でも同じ暗号・comment 書庫を展開できた。
- 全 suite: RAR 1.402 / 1.54 の両 fixture を有効にした `swift test` は
  **2,078 tests / 58 skipped / 0 failures**、Compat は **34 tests / 0 failures**。
  時間制限なしの background で実行し、test 本体は 1,416.690 秒で成功した。
