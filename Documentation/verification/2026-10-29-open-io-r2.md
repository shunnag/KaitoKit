# Open/list I/O round 2 — 2026-10-29

> The original-run tables below are historical. The [adversarial follow-up](#adversarial-review-follow-up) records the corrected test oracle, tar planning policy, current measurements, and rerun results.

Baseline: `perf/r2-open-io`, HEAD `15be97b`; discovery array indices 14–19 were rechecked against this worktree. All six candidates are retained because their intended gains reproduced. Optional parallel scoring was not implemented.

## Changes and invariants

- **14 — done:** `Traits.category` is a local `UInt8` enum with an explicit mapping of all 30 Unicode categories and a future-category fallback. Scoring stays serial, with the same sampling, ordering, arithmetic, and thread/power policy. Allocation counts did **not** improve for this change.
- **15 — done:** inspect the adjacent 56-byte ZIP64 v1 end record before the bounded backward scan. SFX-relative offsets still work; extensible records still use the scan. The original logical scan-budget charge is deliberately retained: charging only physical reads would change limit/retry acceptance. Split-volume handling is unchanged. The fixed record is still validated by the existing parser.
- **16 — done:** materialize a CF-backed decoded batch as native UTF-8 once, then split its contiguous bytes. Piece-count validation, empty pieces, per-name fallback, and bisection remain in place.
- **17 — done:** independent eight-slot FIFO caches share RAR5 and 7z dictionaries through Swift COW. Keys cover every common dictionary value; hash bytes, versions, redirections, copy/link targets, ownership, start positions, and creation/access times remain entry-specific. Logical metadata accounting is unchanged.
- **18 — done:** tar and RAR5 publish lookup keys using their existing split components. Ordinary names reuse their String storage. Original-byte checks still reject NUL and absolute paths; `..` rejection and dot/duplicate-slash normalization are preserved.
- **19 — done:** tar uses `HeaderWindowByteSource` only for resolved high input latency, with physical header spacing supplied to the adaptive planner. Tar selects a 4 KiB small-window floor; other formats retain 16 KiB. This adjustment was necessary: the initial 16 KiB prototype increased sparse-tar transfer from 832,512 to 3,317,760 bytes and modeled time from about 165 to 197 ms. The retained implementation restores the sparse transfer count/bytes. Extension payload reads and parsing/metadata limits are unchanged.

## Method

Host verified as arm64; Apple Swift 6.4 (`swiftlang-6.4.0.34.1`), `swift --version` host target `arm64-apple-macosx27.2.0`. Hardware-model `sysctl` access was denied, so no CPU-model claim is made.

Generated 10k/100k ZIP, forced/automatic ZIP64, RAR5, non-solid Copy 7z, ASCII tar and CP932 tar archives, plus 202 × 256 KiB sparse tar members. RAR5 headers are project-owned synthetic bytes; 7z is generated by the installed `7zz` executable. No prohibited implementation sources were opened. All controlled scratch lived under `/private/tmp/kk-r2io`; builds used this worktree's `.build`.

`OpenProbe.swift` loads each archive as Data with `.mappedIfSafe`, wraps it in a read-counting ByteSource, performs one warm open, then times `ArchiveReader.open` and full entry materialization. Console formatting and entry-digest computation are outside the timed/allocation window. Counts are successful Darwin malloc/realloc allocation events; allocated bytes are cumulative requests, **not** retained memory or peak RSS. The logger's overhead is included in both sides. Each ordinary paired row has three repetitions in alternating A/B order. Separate saved release libraries prevent later builds from changing earlier stages.

Stage mapping: `before` = baseline; `traits` = 14 only; `shared` = 14–17; `floor` = all retained changes. RAR5/7z common-name cases isolate 17; ASCII tar at low latency and RAR5 `shared` → `floor` isolate 18. Fixed-policy CP932 tar isolates 16. Fixed-policy 100k ZIP also includes 15's ZIP64 I/O reduction. High-latency tar baseline → final includes 18; use the separate low-latency row to distinguish that CPU/allocation saving from 19's read coalescing.

The network **model**, not a real NAS measurement, sleeps for 0.5 ms plus bytes / 110 MB/s on every underlying read. It includes scheduling overhead. Warm mapped-input time is not a cold-disk result.

An initial Python ZIP generator left the UTF-8 bit set on CP932 names. Those preliminary ZIP measurements were discarded. The retained ZIP corpus has both local and central UTF-8 bits clear, and all measured variants select CP932. The authored TSV contains **735 data rows plus its header**, rather than 736 data rows.

## Adversarial review follow-up

This follow-up fixes the three confirmed findings while retaining all other R2 changes. Current raw runs, corpus/binary hashes, and test outcomes are in [review-results.json](../../Tests/Measurement/open-io-r2/review-results.json). The earlier tables remain the original-run record, not current measurements of the revised tar planner.

### 1. Storage-independent test oracle

`testTarErrorsAndLimitsMatchAcrossLatencies` now stores optional `[ArchiveEntry]` results and compares them with `==`. It compares reflected strings only for errors. Auditing the other new tests found no other entry/dictionary description used as an equality oracle: category descriptions are scalar enums, other entry checks already use Equatable, and benchmark dictionary hashing sorts the keys.

The original test reproduced the failure under Guard Malloc: one test, two assertion failures differing only in dictionary key order. The corrected oracle and all four other tar latency tests pass with Guard Malloc loaded and `SWIFT_DETERMINISTIC_HASHING` explicitly unset.

### 2. Tiny metadata limits

Tar retains a 4 KiB header buffer independently of its limit for extension payloads. Its HeaderWindowByteSource base-request cap is now at least that buffer size. The common byte-source splitter, RAR5/LHA caps, and their default median planner behavior are unchanged; their header reader capacities already follow their metadata limits.

Direct TarReader / CallCountingByteSource tests (`reportsNonLocalVolume: true`, 100 small members):

| maxMetadataSize | Low reads / bytes | High before reads / bytes | High after reads / bytes |
| ---: | ---: | ---: | ---: |
| 0 | 26 / 103,424 | 103,424 / 103,424 | 26 / 103,424 |
| 1 | 26 / 103,424 | 103,424 / 103,424 | 26 / 103,424 |
| 512 | 26 / 103,424 | 202 / 103,424 | 26 / 103,424 |

Both explicit high latency and automatic latency with the non-local source hint are checked. The extra high-path split-loop calls are gone; extension-payload metadata limits are still enforced by the existing parser.

### 3. Mixed layout read amplification

Tar opts into a conservative estimate: the maximum of the last four physical header spacings, with eight observed headers required before growing a window. This avoids mistaking the tested initial directory/PAX preludes for a run of dense file members. Default median behavior is preserved for RAR4, RAR5, and LHA.

The first four-observation prototype still over-read the native directory/xattr prelude (482,432 versus 224,384 low-latency bytes); it was rejected. The retained eight-observation policy matches low-latency transfer for that case. The native corpus was generated by `/usr/bin/tar --format pax` from 40 physically populated, non-sparse 4 MiB files carrying `com.apple.quarantine` and `com.apple.metadata:kMDItemWhereFroms`. An initial sparse-file generator attempt was excluded and replaced with physical payloads before retaining the native measurements.

The N=1/2/3 direct-reader tests each use 40 groups and compare entries by value across low/high/automatic policies. High must have no more reads than low and no more than 1.5× its bytes. N=1 remains 41 reads / 164,864 bytes; N=2 falls from 422,912 to 164,864 bytes at 41 reads; N=3 falls from 10,228,736 to 164,864 bytes at 41 reads. The strengthened PAX/sidecar test includes the initial directory/PAX prelude: low, high, and automatic all use 162 reads / 358,573 bytes. The dense-tar test still requires a reduction of at least 4×.
