# RAR5 compression version 1 の実装と検証 — 2026-11-02

## 範囲と資料

RAR5 compression version 1 に対応した。資料は RARLab の公開 technote / `rar.txt`、既存の
clean-room な version 0 decoder、RAR 7.23 / UNRAR 7.23 の black-box 入出力である。
第三者の decoder source は参照していない。

`rar.txt` は RAR 7.0 の最大 64 GiB dictionary、4 GiB を超える非2の累乗辞書、4 GiB を超える
場合の long range search を説明している。17 MiB の非2の累乗辞書は RAR 7.23 が拒否し、
16 MiB は version 0 になるため、小さな version 1 fixture は生成できない。`-mdx` は展開専用で、
圧縮には使えない。

## 確定した規則

- version 0 の distance table は 64 symbols、version 1 は 80 symbols。他の table layout は共通。
  したがって combined table は version 0 が 430、version 1 が 446 entries。
- table 長は decoder と並列 Huffman token 解析の両方へ compression version を渡す。
  並列 token は下位 32 bit の距離に加え、version 1 の長い距離の上位 8 bit を bit 48〜55 に保持する。
  version 0 の token layout は変えない。
- 非2の累乗辞書は次の2の累乗の ring に確保する。match distance は宣言辞書で制限し、
  `SolidState` には実 ring と別に宣言上の距離上限を持たせる。これにより solid の後続 member が
  小さな辞書を宣言しても、グループの正当な履歴を拒否しない。
- `maxDictionarySize` は実確保量に適用する。例えば 192 KiB は 256 KiB、5 GiB は 8 GiB。
  solid coordinator も同じ実確保量で制限する。
- version 2 以上は従来どおり拒否する。既定の entry / dictionary 上限を撤廃したわけではない。

初期の version 0 table では実 version 1 の `index=403, run=42` が table を超えた。
run の終端が複数 446 になることと、距離記号を 80 にした実出力で規則を確定した。

## 実 version 1 書庫

RAR 7.23 で `RAR 5.0(v70) -m1 -md=5g` を生成し、1 MiB ごとの streaming SHA-256 で検証した。
大きな fixture は repository に入れず、probe は `KAITO_RAR5_V1_ARCHIVE` と
`KAITO_RAR5_V1_SHA256` が設定されたときだけ実行する。

| 入力 | packed size | 出力 SHA-256 |
| --- | ---: | --- |
| 5 GiB の零データ | 216,000 byte | `7f06c62352aebd8125b2a1841e2b9e1ffcbed602f381c3dcb3200200e383d1d5` |
| seed 20261102 の 1 MiB 非乱数パターンを 5 GiBへ反復 | 20,342,219 byte | `2a3623bd4ff86f93545aac013ddb90cb15148831179c3f7dfb0e0145529d52dd` |

両方とも出力は 5,368,709,120 byte で、原本と全 byte 一致した。非乱数パターンは長い距離の
照合を含み、単なる zero run の成功ではないことを確認した。`maxDictionarySize = 5 GiB` では
実確保の 8 GiB を超えるため拒否され、6 GiB entry / 8 GiB dictionary の指定で展開できる。

## 小さな回帰ベクタ

version 1 の 80-distance table を使う 9 個の literal block を自作し、1 / 4 thread で同じ出力を
確認した。192 KiB 宣言が 256 KiB の ring になること、192 KiB 上限が実確保超過で拒否されることも
検査した。version 0 の既存 decoder / reader tests も変更なく通る。
