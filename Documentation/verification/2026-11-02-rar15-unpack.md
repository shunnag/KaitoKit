# RAR4 unpack version 15 の検証

対象: cooViewer-c1vj.10。RAR 1.3 / 1.5 の adaptive Huffman + LZ77、64 KiB 窓、
ShortLZ / LongLZ / StMode と solid 状態共有を実装する。

## 入力資料と fixture

- [RAR 1.3 format notes §6](https://github.com/bitplane/rar-research/blob/master/doc/RAR13_FORMAT_SPECIFICATION.md)
  を実装仕様にした。7-Zip Rar15、UNRAR、XADMaster、The Unarchiver の source は参照していない。
- `Tests/Fixtures/rar15/` は `Scripts/fixtures/make-rar15.py` が生成する独自 fixture。
  UNRAR 7.23 の `t` と `x` で、通常・solid 両書庫の CRC と元入力の全 byte 一致を確認した。
  生成手順と archive SHA-256 は同ディレクトリの README に記録する。
- 大きい実書庫は `KAITOKIT_RAR15_FIXTURES=<repo>/inbox/rar15` で渡す
  非配布の開発用比較対象。再配布許可を確認していないため git には含めていない。

## 実装で確定した規則

- ChSet / ChSetB / ChSetC の頻度補正では、補正後の表と逆引き位置を読み直す。
  補正前の位置を保持すると範囲外参照や literal の破壊が起きる。
- ShortLZ code 14 は LastDist / LastLength だけを更新し、4 件の repeat-distance 履歴には
  追加しない。共通の match 履歴更新へまとめると、後続の短い参照が誤った距離を選ぶ。
- 入力末尾の `peek(16)` の padding は許可するが、実際に消費した bit が圧縮入力を超えれば
  `truncated` とする。peek の overrun だけで拒否すると、末尾の有効な match を失う。
- 未書き込み領域を参照する match の zero-fill は match 開始時に決め、出力 buffer の境界や
  窓の一周によって途中で実データへ切り替えない。

## 確認した結果

- `RAR15DecoderTests`: **7 tests / 0 failures**。
  - 自作通常書庫の literal / ShortLZ、1 byte 読み出し。
  - 自作 solid 書庫の順読み、逆順読み、再読。
  - RAR 1.54 `readme_154_normal.rar` の 1 file が UNRAR 出力と全 byte 一致。
  - `audio_win_names_unpack15.rar` の音声 1 file、`doc_154_best.rar` の 17 file が全 byte 一致。
  - 音声と長い文書を decoder から 97 byte ずつ読んでも一致。
  - 圧縮長 0 / 1 / 半分への切り詰めを `truncated` で拒否。
- `RAR20DecoderTests`: **5 tests / 0 failures**。既存 version 20 / 26 と solid に退行なし。
- `RAR4LegacyVersionTests`: **1 test / 0 failures**。version 15 が decoder へ到達し、
  不完全な圧縮 body を `truncated` で拒否する。
- `kaito sha` で圧縮 payload だけを変えた 256 件を実行（seed 150154、各 2 秒の上限）。
  **crash 0 / hang 0 / 誤った正常出力 0**。受理された 4 件は元入力と SHA-256 が一致し、
  252 件は通常の展開 error だった。
- ASan 付き CLI（`swift build --scratch-path .build/rar15-asan --sanitize=address --product kaito -j 4`）
  で 3 書庫と同じ 256 件を実行し、**sanitizer finding / crash / hang 0**。
- Release CLI（`swift build -c release --scratch-path .build/rar15-release --product kaito -j 4`）
  でも音声・17 文書の SHA-256 が UNRAR 出力と一致した。
- 全 suite: `KAITOKIT_RAR15_FIXTURES=<repo>/inbox/rar15 swift test` は
  **2,066 tests / 58 skipped / 0 failures**、Compat は **34 tests / 0 failures**。
  既定の 600 秒上限を超えるため、最終実行は時間制限なしの background で行った
  （test 本体は 1,418.800 秒で成功）。

## 対象外

custom RAR VM、version 15 の旧暗号、solid 書庫内の分割 member は明示的に拒否する。
これらと CAB Quantum は別課題とする。
