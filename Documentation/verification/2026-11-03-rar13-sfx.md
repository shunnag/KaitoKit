# RAR 1.3 / 1.4 SFX の検証

対象: cooViewer-c1vj.14。DOS stub 前置の `RE~^` 書庫を、実行せずに安全な構造検査で検出して展開する。

## 入力資料と検査

- [RAR 1.3 / 1.4 format notes §10](https://github.com/bitplane/rar-research/blob/master/doc/RAR13_FORMAT_SPECIFICATION.md)
  の MZ layout と `RSFX` marker を使う。第三者の decoder source は参照していない。
- `RAR13Reader.sfxOffset` は MZ 先頭、offset 28 の `RSFX`、画像サイズ、その位置の `RE~^` を照合する。
  画像サイズは `e_cblp == 0 ? e_cp * 512 : (e_cp - 1) * 512 + e_cblp` とし、128 KiB を上限とする。
  `e_cp == 0`、`e_cblp >= 512`、画像サイズ外、署名の不一致を受理しない。
- Data では `scanForSFXInData` の opt-in、URL では既存の SFX 方針で検出する。
  `RebasedByteSource` で stub を除いた後は、通常の RAR 1.3 / 1.4 reader、checksum、暗号、comment を共有する。
- 実 RAR 1.402 の `SFXSRC.EXE` は `KAITOKIT_RAR13_FIXTURES=<repo>/inbox/rar13` で比較する。
  `RSFX`、実画像サイズ 6,491、署名位置を UNRAR 出力と照合する。git には含めない。

## 確認した結果

- `RAR13ReaderTests`: **17 tests / 0 failures**。
  - synthetic stub で Data の opt-in 必須、stored・圧縮の展開を確認。
  - `e_cblp == 0` の最終 page 満了でも正しい offset で展開。
  - 不正 marker、page 数 0、不正な最終 page、画像サイズ外、署名不一致を拒否。
  - 実 RAR 1.402 `SFXSRC.EXE` が UNRAR 出力と全 byte 一致。
  - 既存の通常・solid・暗号・comment・checksum 検査にも退行なし。
- `RAR15DecoderTests`: **7 tests / 0 failures**。
- ASan 付き CLI（`swift build --scratch-path .build/rar13sfx-asan --sanitize=address --product kaito -j 4`）
  と Release CLI（`swift build -c release --scratch-path .build/rar13sfx-release --product kaito -j 4`）
  で、実 RAR 1.402 SFX と synthetic SFX が UNRAR 出力と一致した。
- 全 suite: RAR 1.402 / 1.54 の両 fixture を有効にした `swift test` は
  **2,083 tests / 58 skipped / 0 failures**、Compat は **34 tests / 0 failures**。
  時間制限なしの background で実行し、test 本体は 1,419.172 秒で成功した。

## 対象外

old multi-volume は cooViewer-c1vj.13 とする。SFX の実行・実行ファイルの一般走査は行わない。
