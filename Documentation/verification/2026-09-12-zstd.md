## 実装範囲 / Implementation

`Sources/KaitoKit/Codecs/Zstd/` の六ファイルは、前向き入力と逆向きビット読取り、FSE 分布・
状態表、Huffman direct / FSE weights と 1 / 4 stream、literals / sequences、frame と XXH64 を扱う。
LL / ML / OF の accuracy log 上限は 9 / 9 / 8、Huffman weights の FSE は 6、Huffman 符号は 11 bit。
offset code は 0〜31。辞書 ID が非零なら `unsupportedMethod("zstd dictionary <id>")`。

ByteSource の指定範囲から最大 64 KiB ずつ読み、block 単位で出力する。
履歴は window サイズのリング。block / literals の作業領域は各最大 128 KiB。
確保前に `ReadLimits.maxDictionarySize`（既定 1 GiB）を確認する。
重なる match は直前に出力した byte を参照し、履歴と window を越える距離を拒否する。
frame が変わると Huffman / FSE table・repeat offset・checksum をリセットする。

連結 frame と skippable frame は一つの連続出力になる。全 frame が content size を持てば
一覧の uncompressedSize に合計を保存し、一つでも欠ければ nil。宣言サイズと実出力も検証する。
`.tar.zst` / `.tzst` は既存の SingleFileMaterializer / TarReader を通る。
RPM は payload magic を優先して cpio に降り、ZIP method 93 は中央 directory の期待サイズと CRC も検証する。
通常の entry / 総量 / in-memory 上限と reopen を既存 API で維持する。

> Six codec files implement FSE/Huffman, literals/sequences, frame processing and streaming XXH64.
> Input and history are bounded, overlapping copies preserve byte order, and state resets between frames.
> Standalone/tar streams, RPM cpio payloads and ZIP 93 share the decoder and existing resource limits.
> External dictionaries and zstd inside 7z remain unsupported.

## 差分と破損入力 / Differential and malformed-input tests

実行時 matrix は 5 入力 × 4 level × 2 checksum × 2 content-size = **80 通り**。
text 200 KiB、binary 256 KiB、random 64 KiB、repetitive 1 MiB、mixed 512 KiB の元入力と byte 比較する。
zstd がなければこのテストのみ XCTSkip、7zz がなければ第二オラクルのテストのみ XCTSkip とする。

`ZstdTests` は固定全件の一覧・SHA-256・reopen・127-byte stream と、全 44 正常標本の第二オラクルを検査する。
46 件それぞれに 25 / 50 / 90% / 最後の 1 byte の切断（184 件）、24 箇所の bit 反転（1,104 件）を適用する。
frame / sequence の Reserved bits、block-size / window 超過、Huffman の不正重み合計、FSE の分布合計超過、
履歴超過、repeat offset が零になるケース、宣言サイズ不一致、checksum、Dictionary_ID を直接構築して検証する。
FSE 破損は checksum だけに頼らず table parser / builder でも確認する。

仕様から手作りした正常ケースには、direct weights、最大 11 bit の Huffman、1 / 4 stream、RLE literals、
RLE / Repeat sequence table、1 / 2 / 3-byte sequence count、全 skippable magic、全 content-size 幅、
window descriptor の mantissa、リング折り返し、window と等しい offset、repeat offset の -1 特例を含む。
7-byte の短い ByteSource read、64 KiB refill を跨ぐ raw block、範囲外アクセス禁止、terminal error も検査する。

bit 反転は必ずしも破損を意味しない。RFC の Unused bit（bit 4）は無視する必要があり、
skippable 本文や checksum 無しの合法な内容変更も受理できる。
これらまで一律拒否するのではなく、切断と構造的に不正なケースは KaitoError、任意反転は
正常終了または KaitoError に限られることを確認する。crash / hang は許容しない。

> The runtime matrix has 80 cases and compares exact original bytes. Tests also cover 184 truncations,
> 1,104 bit flips, malformed entropy tables, lengths, offsets, checksums, dictionary IDs and resource limits.
> Hand-built valid cases exercise boundary encodings and ring wrap. Arbitrary flips may remain valid
> in unused bits, skippable metadata or unchecked content; those are not falsely required to fail.

追加の black-box probe では、重み `[2, 2]`（最後の重みは 3）を持ち、重み 1 の葉がない
非正規の Huffman 表に対し、zstd は corruption を返し、7zz は `00 01 02` を返した。
本実装は、導出された木の深度と最長符号長の一致、および最深段の兄弟の葉を要求して拒否する。
この差は第二オラクルの寛容な入力受理として記録し、正常 fixture の一致とは区別する。

> One malformed-tree probe differed between oracles: weights [2, 2] imply no deepest-rank leaves.
> zstd rejects it while 7zz decodes it. KaitoKit requires a consistent tree depth and paired deepest
> leaves, and rejects this noncanonical representation. Valid-fixture comparisons remain identical.

| 測定 | 中央値 |
|---|---:|
| KaitoKit open | 0.106 ms |

`f94d31471082c56b0457f594722c8501f6291dbf48f0e9d226b92f37c289cef6`。

