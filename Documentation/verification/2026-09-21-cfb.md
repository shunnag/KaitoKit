# Microsoft Compound File（MS-CFB）の読み取り（2026-09-21）

環境: macOS 27.2 / Apple Silicon / 7-Zip 26.03 `7zz`（黒箱 reader。CFB は読めるが書けない）。

## 実装と範囲

- 公開 `ArchiveFormat` に `.compoundFile`（raw value `"cfb"`、CLI の `detect` は `cfb`、compat の `formatName()` は
  `Compound File`）を追加。検出は offset 0 の署名 `D0 CF 11 E0 A1 B1 1A E1`。
- `CFBReader`（`Sources/KaitoKit/Formats/CFB/CFBReader.swift`）: header（§2.2。version 3 = 512 byte sector、
  version 4 = 4096 byte sector。byte order `FFFE`、mini sector shift 6、cutoff 4096 を検証）→ DIFAT（header の
  109 個 + DIFAT sector の chain、§2.5）→ FAT を 1 本の配列に（§2.3）→ directory の chain（§2.6）→ mini FAT と
  root entry が指す mini stream（§2.4）。root の子から red-black tree を左 → 自分 → 右で辿り、storage を
  `.directory`、stream を `.file`（`stored`）として公開する。storage の CLSID（全 0 でなければ registry 形式で
  `formatSpecific["clsid"]`）、作成 / 更新日時（FILETIME、`created` と `modificationDate`）。
- stream の読み取り: cutoff 未満は mini FAT の chain を mini stream の sector 列に写し、それ以外は FAT の chain。
  連続する sector は 1 つの範囲にまとめ、断片化していれば `CFBRunDecompressor` で順に返す。version 3 の
  size は §2.6.3 の推奨どおり下位 32 bit だけを使う。
- 名前: UTF-16LE。制御文字（`U+0000`〜`U+001F`、`U+007F`）と `/` は path に置けないので `[n]` に置き換える
  （`\u{05}SummaryInformation` → `[5]SummaryInformation`。7-Zip の一覧と同じ綴り）。Windows Installer の
  詰め込み名（`unpackMSIName`）は unit ごとに戻し、戻した名前は `formatSpecific["storedName"]` に元の UTF-16 名を残す。
- 検査と上限: sector 番号は file の大きさと `MAXREGSECT` で、chain は訪問済み集合（循環）と宣言 sector 数で、
  directory の木は訪問済み集合と `maxPathComponentCount`（深さ）・`maxEntryCount` で、metadata（DIFAT / FAT /
  directory / mini FAT）の読み取り量は `maxMetadataSize`（`CFBMetadataBudget`）で、directory entry 数は
  `maxMetadataRecordCount` で、stream の宣言サイズは `maxEntrySize` で抑える。chain が宣言サイズより短ければ
  `truncated`、mini sector が mini stream の外なら `malformed`。
- 対象外: MSI 内の cabinet の連鎖、Office の property set / OLE の中身の解釈、range lock sector（読まない）、
  transaction signature。

## 出自

[MS-CFB] v20240423（`inbox/cfb/MS-CFB.pdf`、SHA-256
`9d0d61e34495347ee32f3de5b06f2d59953cc60607ea72605d4162d21a34863f`）§2.1〜2.9 の散文と表だけを実装入力にした。
7-Zip / libgsf / olefile / Apache POI などの CFB 実装 source は開いていない。黒箱で決めた点:

| 点 | 扱い |
| --- | --- |
| 制御文字で始まる名前の綴り | 7-Zip の一覧が `[5]SummaryInformation` と出すのに合わせた |
| MSI の詰め込み名（裁定 4、利用者承認 2026-09-21） | 実物 MSI（下記）の 23 名を 7-Zip の一覧と並べ、「U+3800〜U+47FF = 2 文字（下位 6 bit が先）、U+4800〜U+483F = 1 文字、U+4840 = `!`、字母 0-9 A-Z a-z . _」の仮説で 23 / 23 一致。数字・A〜Z・a〜z の全字・`.`・`_`・単独 `!`・U+47FF（→ `__`）・範囲外の U+4841 / U+3400（そのまま）・`a`+U+4801（→ `a1`）を自作 file で探り、字母 64 字すべての戻し方と、root CLSID が 0 でも MSI の CLSID でも 7-Zip は同じに戻すことを確認（`msi-names.cfb`） |
| 孤立 sector | どの stream にも属さない FAT 上の sector（ENDOFCHAIN だけの chain）を多数持つ file を 7-Zip は "Cannot open the file as archive" で拒む。fixture は実 stream だけで構成した（reader 側は孤立 sector を気にしない） |
| 末尾の空 sector | 最後の非 FREESECT entry より後ろに sector を書くと 7-Zip が "data after the end of archive" と警告する。writer はそこで file を終える |

## 残る制約

- 実物は上の 3 file（Office 2 種と MSI 1 種）だけで確認した。reader は red-black tree の色を見ず、unallocated
  entry は飛ばす。
- MSI の詰め込み名の写像は 7-Zip の挙動との一致で確定したもので、Windows Installer の仕様文書による裏付けは無い。
  MSI 内の cabinet（`setup.cab` など）は stream として見えるだけで連鎖しない。
- version 3 で size の上位 32 bit を無視する（仕様の推奨）。version 4 は 64 bit のまま。
- range lock sector と 2 GiB 超の version 3 file は扱わない（sector 番号の検査で `truncated` になる）。
