# RAR4 version 15 の solid 分割の検証

対象: cooViewer-c1vj.16。RAR 1.5 solid 書庫の 2 件目を old `.rar` / `.r00` に分け、
結合した packed stream と継続した solid 状態で展開する。

## 入力資料と fixture

- [RAR 1.5–4.x format notes §7 / §21](https://github.com/bitplane/rar-research/blob/master/doc/RAR15_40_FORMAT_SPECIFICATION.md)
  の `EARC_NEXT_VOLUME`、`FHD_SPLIT_BEFORE` / `FHD_SPLIT_AFTER`、volume ごとの header を使う。
  第三者の decoder source は参照していない。
- `Scripts/fixtures/make-rar15-volumes.py` は既存の独立 encoder の `solid.rar` を 2 巻に分ける。
  先頭巻の ENDARC を省略し、末尾 file の `SPLIT_AFTER` から次巻を判断する経路を検査する。
  UNRAR 7.23 の `t` / `x` でも `first.txt` / `second.txt` が元入力と一致することを確認した。
- 結合済み record は `isSplit == false` で、2 つの `SourceSegment` を持つ。
  非最終 part の CRC を検査し、最終 part の全文 CRC と既存の `RARSolidCoordinator` も使う。

## 確認した結果

- 修正前は、先頭巻で ENDARC がないと `RAR4EntryPublisher` が未完の分割 file を `truncated` で拒否した。
  parser が ENDARC の `EARC_NEXT_VOLUME` だけで次巻を判断していた。
- 修正後は、物理 EOF で未完の末尾 file に `SPLIT_AFTER` があれば次巻を解決する。
  ENDARC がある場合は従来どおり `EARC_NEXT_VOLUME` を使う。Data からの継続巻は `unsupportedMethod`。
- `RAR15DecoderTests`: **9 tests / 0 failures**。順読み・逆順読み・再読、結合 record、
  ENDARC を除いた非分割書庫、Data の拒否を確認。
- `RAR4VolumeTests`: **8 tests / 3 skipped / 0 failures**。実 corpus 未設定の 3 件は skip。
  合計では **17 tests / 3 skipped / 0 failures**。
- 文書・移行ガイドの対象 test: **15 tests / 0 failures**。
- ASan 付き CLI（`swift build --scratch-path .build/rar15volumes-asan --sanitize=address --product kaito -j 4`）
  と Release CLI（`swift build -c release --scratch-path .build/rar15volumes-release --product kaito -j 4`）
  で 2 巻の solid 分割が一致した。ENDARC を除いた非分割書庫も ASan で一致した。
  payload / file CRC の 128 変異は **sanitizer finding / crash / hang / 誤った正常出力 0**
  （受理 1、通常の展開 error 127）。
- 全 suite（PR #91 取込前）: KaitoKit **2,085 tests / 59 skipped / 0 failures**、
  Compat **34 tests / 0 failures**。test 本体は **1,423.551 秒**。

## 対象外

custom RAR VM、version 15 の旧暗号、Data からの継続巻解決は変更しない。
