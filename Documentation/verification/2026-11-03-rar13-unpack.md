# RAR 1.3 / 1.4 の検証

対象: cooViewer-c1vj.11。`RE~^` container、stored・Unpack15 圧縮、16-bit rolling checksum、
solid の検出と展開を実装する。

## 入力資料と fixture

- [RAR 1.3 / 1.4 format notes](https://github.com/bitplane/rar-research/blob/master/doc/RAR13_FORMAT_SPECIFICATION.md)
  を実装仕様にした。第三者の decoder source は参照していない。
- `Tests/Fixtures/rar13/` は `Scripts/fixtures/make-rar13.py` が生成する独自 fixture。
  UNRAR 7.23 の `t` と `x` で通常・両 solid 書庫の CRC と全 byte を照合した。
  生成手順と archive SHA-256 は同ディレクトリの README に記録する。
- 実 RAR 1.402 書庫は `KAITOKIT_RAR13_FIXTURES=<repo>/inbox/rar13` で渡す非配布の比較対象。
  [fixture の説明](https://github.com/bitplane/rar-research/blob/master/fixtures/1.402/README.md)
  と同じ 9 書庫を UNRAR で展開して比較する。git には含めていない。

## 実装で確定した規則

- signature は RAR4 / RAR5 と異なる `RE~^`。main header 7 byte 以降を file header + payload として
  EOF まで読む。16-bit rolling checksum は byte ごとの加算と 1 bit 左 rotate で、CRC32 ではない。
- 実 RAR 1.402 の `SOLID.RAR` は main flags `0x88`、各 file flags `0x00` だった。
  main header の `MHD_SOLID` だけでも、最初の圧縮 file を group 先頭として以後の window・adaptive 表を共有する。
  file flag の `LHD_SOLID` がある形式も同じ coordinator で扱う。
- directory は本文を持たず、stored member は solid の LZ 状態を変更しない。archive comment は main header
  全体を読み飛ばすが、file comment の本文展開は今回の対象外とする。

## 確認した結果

- `RAR13ReaderTests`: **8 tests / 0 failures**。
  - 自作 stored・独立圧縮を 1 byte ずつ読み、元入力と全 byte 一致。
  - file flag あり・main header のみの両 solid で順読み・逆順読み・再読が一致。
  - rolling checksum の不一致、暗号化・分割・file comment の明示的な拒否、切り詰めと不正な
    version / stored size を確認。
  - RAR 1.402 の `README.RAR`、`README_store.rar`、`BIG80K.RAR`、`REPEATB.RAR`、`SOLID.RAR`、
    `WITHDIR.RAR`、`COMMENT.RAR`、`MULTIFIL.RAR`、`EMPTY.RAR` が UNRAR 出力と全 entry 一致。
    実 solid の逆順読みも一致。`FCOMM.RAR` は一覧できるが読み取りは `unsupportedMethod`。
- `RAR15DecoderTests`: **7 tests / 0 failures**。RAR4 version 15 と RAR 1.3 の decoder 共有に退行なし。
- ASan 付き CLI（`swift build --scratch-path .build/rar13-asan --sanitize=address --product kaito -j 4`）
  で実 RAR 1.402 の 9 書庫を展開し、checksum・flag・圧縮 payload を変えた 256 件を実行。
  **sanitizer finding / crash / hang / 誤った正常出力 0**（受理 7、通常の展開 error 249）。
- Release CLI（`swift build -c release --scratch-path .build/rar13-release --product kaito -j 4`）
  でも同じ 9 書庫を全件展開できた。
- 全 suite: RAR 1.402 / 1.54 の両 fixture を有効にした `swift test` は
  **2,074 tests / 58 skipped / 0 failures**、Compat は **34 tests / 0 failures**。
  時間制限なしの background で実行し、test 本体は 1,418.619 秒で成功した。

## 対象外

旧暗号、old multi-volume、SFX はそれぞれ cooViewer-c1vj.12 / .13 / .14 とする。
custom RAR VM と CAB Quantum は別課題のまま。
