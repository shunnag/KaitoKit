## Per-file changes

- `Sources/KaitoKit/Codecs/RAR/RAR29Decoder.swift`: LZ tokens now write only to
  a bounded contiguous ring span. An outer loop flushes that initialized span
  to caller output or filter capture. Filter descriptors and block switches stop
  the inner loop and execute after flushing. Huffman pointer/width snapshots,
  bit cursor, repeat distances, history and positions are local; no decoder
  property or Array access occurs inside the LZ run. Matches initialize one
  period **inside the ring**, double initialized ring spans, then emit in bulk.
  The rejected immediate match-emission design is not used. PPMd ordinary
  literals use one scoped model/range borrow until the first escape or the same
  output/filter boundary. The consumed escape is followed by the existing
  action parser; action/payload bytes never enter the literal output run.
- `Sources/KaitoKit/Codecs/PPMd/VariantH/PPMd7Model.swift`: adds the nonescaping
  `withRARCursor` API and makes the existing noncopyable model cursor visible
  inside the module. No probability/model-update algorithm changes.
- `Sources/KaitoKit/Codecs/PPMd/VariantH/RARPPMdRangeDecoder.swift`: moves the
  existing coder scalars/input offset into a noncopyable value cursor and adds
  its scoped borrow. The class still supports the original byte API for control
  bytes. All validation, arithmetic, normalization points and four-byte
  initialization reads are preserved.
- `Sources/KaitoKit/Codecs/RAR/RARStandardFilters.swift`: RGB uses validated raw
  pointers for its component and color-recombination loops. Predictor arithmetic,
  dirty-buffer initialization for unusual widths and parameter errors are unchanged.
- `Tests/KaitoKitTests/RAR/R3Baseline/R3BaselineRAR29Decoder.swift` and
  `R3BaselineRARPPMdRangeDecoder.swift`: frozen HEAD oracles. Adaptations are
  renamed types/imports and an alias to the unchanged filter-program record type.
  Shared model algorithms and filter helpers are not duplicated; historical RGB
  goldens and the independently built HEAD executable additionally check the
  RGB pointer change.
- `Tests/KaitoKitTests/RAR/RAR29R3Tests.swift`: 1,119 deterministic original,
  truncation and bit-flip comparisons at buffers 1/4099/262144, including solid
  LZ/PPMd history established separately by each decoder. Compares returned
  bytes, exact error text, terminal latching, finish state, bit/output/pending
  cursors and range byteOffset. Exhaustively compares all positions, distances
  and contiguous counts in a 32-byte ring against independent forward copying
  (16,896 cases), including self-copy, wrapped sources and short periods.
- `Tests/Measurement/rar4-r3/`: reproducible generator (using repository R0 generators
  plus macOS `sips`), identity verifier, alternating timing harness, manifests,
  profiles and actual timing/identity results.

Existing native Delta, Audio, E8/E8E9, ARM, Itanium and stacked-filter application
code is unchanged. The existing R1/CommonPrimitive/filter fixtures exercise those
paths, including dirty RGB work areas and raw history after transformed output.

## Unsafe bounds and state/commit argument

1. The caller/capture capacity and distance to the next filter bound each run.
   `runStart <= position <= runEnd <= windowSize`; a run cannot overwrite bytes
   awaiting its own flush. Literals store only with `position < runEnd`. The
   output-size check still precedes the write. A wrap adds an internal flush,
   not a returned read or extra decoded token.
2. Every match has the unchanged token-level checks:
   `0 < distance <= historySize <= windowSize`, positive length and full length
   within declared output. A chunk has `count <= runEnd - position`. The initial
   period is at most distance and reads only initialized history. Its first
   source span ends at the ring end. If it wraps, the second source span ends
   at or before the destination's initial position, so the first destination
   write cannot destroy that source. `memmove` permits physical overlap and
   full-dictionary-distance self-copy. Each doubling batch is at most the
   initialized destination prefix, with nonoverlapping source/destination spans;
   all destinations end by `position + count <= windowSize`.
3. A flush copies exactly `position - runStart` initialized bytes. This count
   is bounded by the caller's free capacity or the current filter's free work
   area. Filter buffers remain separate once-allocated work areas. Scheduled
   ranges, stacked-filter ordering and transform completion are handled only
   by the unchanged outer control logic.
4. Huffman snapshots retain pointers into tables owned for the whole read.
   A control token ends the inner run before rebuilding any table. The existing
   canonical-code bounds, 10/15-bit lookups, eight-byte input sentinel and sticky
   logical overrun checks are unchanged. Every inner LZ token iteration observes
   logical exhaustion, including no-op repeat tokens and pending matches.
5. The PPMd borrow is nonescaping and both value cursors are noncopyable. State
   is mutated in place: throwing does not roll back partially consumed range or
   model state. Literal position/history advance only after a complete model
   byte succeeds, as before. The first escape ends the borrow before its action;
   matches, filters, table transitions and model replacement keep the original
   token order. Run limits prevent reading past caller/filter boundaries.
   byteOffset is converted to bitOffset at the original read/block/error commit
   points. Persistent solid-model ownership/replacement is unchanged.
6. RGB's three component progressions partition `[0,count)`, consume exactly
   count encoded bytes and initialize every output byte. The current iteration
   therefore has `encodedIndex < count`. Upper-neighbor checks bound both raw
   loads; the color pass requires `red + 2 < count`. The original zero-fill rule
   for narrow/unaligned widths remains in force.

## Reproduction and verification commands

The retained generator takes a new/empty directory and records every writer and
`sips` command, result, fixed input timestamp, seed, switch and SHA-256. It creates
three 1024×1024 R0 color images, 16 MiB fixed-seed text, 8 MiB stereo PCM and
12 MiB synthetic x86 bytes. TIFF/JPEG/PNG derive from the same BMPs; PNG is solid,
JPEG is non-solid. All use RAR 6.24 `-ma4 -m3 -cfg- -idq -mt1 -tsc- -tsa-`.

and manifest, including text PPMd `-mct+`. Image conversion can vary with the

## Release performance

Final timing uses five alternating A/B rounds of `kaito bench --threads 1 ARCHIVE 7`,
with warmed archives and separate processes. Each reported extraction time is
then the median of five per-process medians. The harness also records whole-process
`kaito sha --sink --threads 1 ARCHIVE` and `unrar p -inul -p- ARCHIVE` wall times,
both including startup, input, CRC and discarded output. SHA calculation is
disabled for the sink run. The whole-process ratio supplies the measured unrar
gap; it is kept separate from bench's extraction-only duration.

| Workload | Input bytes | HEAD ms | R3 ms | Change | Paired B/A |
|---|---:|---:|---:|---:|---:|
| TIFF RGB | 9,448,080 | 44.713 | 42.849 | -4.2% | 0.9573 |
| JPEG non-solid | 973,333 | 5.211 | 5.177 | -0.7% | 0.9935 |
| Text LZ | 16,777,216 | 35.319 | 29.527 | -16.4% | 0.8360 |
| Text PPMd | 16,777,216 | 464.809 | 194.114 | -58.2% | 0.4179 |
| Solid PNG | 3,790,376 | 19.066 | 19.231 | +0.9% | 1.0046 |
| x86 E8 | 12,582,912 | 34.032 | 29.097 | -14.5% | 0.8521 |
| WAV Audio | 8,388,652 | 71.576 | 69.223 | -3.3% | 0.9773 |

TIFF, text LZ, text PPMd and E8 improve beyond the observed same-binary noise.
JPEG, PNG and WAV are neutral at this noise level. PNG's displayed median
columns rise 0.9%, while its median paired ratio rises 0.46%, within its A/A
paired range of -1.74%...+0.60%. Medians of individual process medians and
medians of paired ratios need not coincide. No case regresses beyond this
empirical noise range. This is a local paired experiment, not a confidence-bound
or idle-machine certification.
